POST /v1/providers/fetch-models​

post/v1/providers/fetch-models

Fetch the model list from a provider's /v1/models endpoint

Proxy a GET against the upstream OpenAI-compatible ``/v1/models``. Browsers can't call third-party LLM endpoints directly (CORS), so the UI's "获取" button posts here and the manager performs the request server-side. Auth resolution order: 1. ``body.api_key`` (caller-supplied, plaintext) 2. ``body.provider_id``: load the stored key for that provider, but only if it belongs to the caller's tenant — otherwise treat it as not found to avoid leaking secrets across tenants. 3. No key — many local providers (vLLM, Ollama) don't require one.

POST /v1/providers/deploy​

post/v1/providers/deploy

Stream deployment of selected providers to selected NineClaw instances

Push the selected providers + main model to each target nineclaw, streaming progress via Server-Sent Events. Sequential per instance — the user-facing wizard renders each event as "deploying" → "deployed"/"failed" so they should arrive one-by-one instead of all at once. On failure of a single instance we emit a ``failed`` event and continue with the next. Event payload (per instance):: { "instance_id": str, "name": str, "status": "pending" | "deploying" | "deployed" | "failed", "error": str | null } A final ``done`` event terminates the stream.

GET /v1/providers/health_check​

get/v1/providers/health_check

Stream concurrent health probes for the tenant's providers

Run an HTTP-GET health probe against every provider's ``base_url`` and stream the result as SSE. Probes run concurrently (bounded by ``_HEALTH_CONCURRENCY``) so a slow provider can't hold up the rest. Each completion immediately streams a ``status`` event, then we batch a single DB UPDATE per provider at the end so subsequent ``GET /providers`` already shows fresh values.
