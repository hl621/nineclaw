Providers API

模型供应商的 CRUD、探活、部署，以及 WebUI Playground 用的能力代理 （对话 / Embedding / Rerank / ASR / TTS）。所有路由都通过 X-Tenant-ID header 做租户划分（缺省走 default_tenant_id）。

响应统一是 {code, message, data} 信封；SSE 端点是例外（text/event-stream）。

用户侧操作说明见手册：Models管理、ASR 语音转写。
知识库详情页对音视频只做文件播放预览，见 RAG（知识库），不是本页的 /providers/audio/transcriptions。

数据模型​

class Provider(SQLModel, table=True):
    id: UUID
    tenant_id: str            # FK tenants.id
    name: str                 # 租户内唯一
    description: str
    base_url: str             # OpenAI 兼容端点，如 https://api.openai.com/v1
    api_key: str              # 永远不出库
    models: list[str]         # JSON 列；用户开启的模型子集
    model_types: dict | None  # 可选：按模型名覆盖 playground 类型
    enabled: bool
    last_health_status: str   # online | abnormal | offline | unknown
    last_checked_at: datetime | None
    created_at: datetime
    updated_at: datetime

api_key 在 ORM 里以明文存（单租户/可信网络下的简化）。ProviderResponse 不返回它，仅暴露 has_api_key: bool。

目录 vs 已开启： POST /providers/fetch-models 返回上游完整目录；models 字段只保存用户开启的子集。详情页添加 / 编辑时用「获取」拉目录；多模型对比 UI 只读各供应商已开启的 LLM / VLM，不会调用 fetch-models，也不会自动把未开启模型写回 models。对比页在「已选 ≥ 2 且全部为 VLM」时可上传 / 粘贴图片，经 POST /providers/chat/completions 以多模态 image_url 并发请求。

路由​

GET /providers​

列出当前租户的所有 provider。

{
  "code": 0, "message": "success",
  "data": {
    "items": [{ ...ProviderResponse }],
    "total": 5
  }
}

POST /providers​

创建。name 在租户内必须唯一。

{
  "name": "OpenAI",
  "description": "...",
  "base_url": "https://api.openai.com/v1",
  "api_key": "sk-...",
  "models": ["gpt-4o", "gpt-4o-mini"],
  "enabled": true
}

base_url 会自动 rstrip("/")。models 会被去重 + 保序。

GET /providers/{id}​

取单个。404 如果不存在或不属于当前租户。

PUT /providers/{id}​

部分更新。所有字段 optional，缺省即不动：

  • api_key: null → 不动（保留原值）
  • api_key: "" → 显式清除
  • api_key: "sk-..." → 替换

DELETE /providers/{id}​

{ "code": 0, "data": { "deleted": "<uuid>" } }

POST /providers/fetch-models​

代理调用上游 /v1/models 拿可用模型清单。

// request
{
  "base_url": "https://api.openai.com/v1",
  "api_key": "sk-...",          // 可选，留空 + provider_id 时用存的 key
  "provider_id": "<uuid>"        // 可选
}

// response
{
  "models": ["gpt-4o", "gpt-4o-mini", "..."],
  "total": 32,
  "upstream_url": "https://api.openai.com/v1/models"
}

URL 拼接：base_url 以 /v1 结尾就追加 /models，否则追加 /v1/models。 带 Authorization: Bearer <api_key> 头。

错误映射：

  • 上游 401 → 401（"API Key 无效或权限不足"）
  • 上游 404 → 404
  • 其他 4xx/5xx → 502（带上游响应 200 字符）
  • 连接错误 / 超时 → 502（"无法连接 $url: ExceptionClass"）

GET /providers/health_check (SSE)​

并发对每个 provider 的 /health 探活。

event: status
data: {
  "provider_id": "...",
  "status": "online" | "abnormal" | "offline",
  "checked_at": "2026-05-27T11:50:32.078107",
  "response_text": "HTTP 200 https://.../health\n{...body...}"
}

event: status
data: ...

event: done
data: { "checked": 12 }

实现：

  • 读 provider 列表（一次 SELECT）
  • asyncio.Semaphore(10) 限并发
  • 每个 probe 通过 asyncio.Queue 推回 coordinator → 立刻 yield SSE
  • 全部完成后 批量 UPDATE 所有 last_health_status + last_checked_at （单事务，避免 N 次小事务）
  • done 事件结束流

URL 选择：base_url 去掉尾部 /v1 后 + /health，timeout 5s。

状态映射：

HTTP结论
200online
401online（服务器活着，鉴权要求是合理的）
其他abnormal
超时offline
连接错误offline

response_text 仅出现在 SSE 事件里，不落库——给前端开发者调试用。

POST /providers/deploy (SSE)​

把选中 provider 写到选中实例的 hermes 配置里。

{
  "provider_ids": ["<uuid>", "<uuid>"],
  "instance_ids": ["7cabbe1bfee148e3"],
  "main_model": { "provider": "OpenAI", "model": "gpt-4o" },     // 可选
  "auxiliary_models": [
    { "task": "vision", "provider": "OpenAI", "model": "gpt-4o-mini" }
  ]
}

事件流：

// 入口快照（每实例一条 pending）
event: status
data: { "instance_id": "...", "name": "...", "status": "pending", "error": null }

// 串行处理（每实例 deploying → deployed/failed）
event: status
data: { ..., "status": "deploying" }

event: status
data: { ..., "status": "deployed" }

// 全部完成
event: done
data: { "finished": true }

每实例处理流程：

  1. 状态非 running → 直接 failed (实例当前状态为 X)
  2. GET /api/config （hermes）
  3. config.custom_providers 替换为按 provider 分组的列表，每条含 name、base_url、models（字典，key 为 model id）、可选 api_key
  4. config.model 设为含 default、provider、base_url、api_key 的对象（如果传了 main_model）
  5. PUT /api/config
  6. 对每个 auxiliary_models[i] 调 POST /api/model/set 含 scope:"auxiliary"、task、provider、model
  7. 任一步抛 HermesError / RequestError → failed，不中断后续实例

main_model / auxiliary_models 引用的 (provider, model) 必须在 provider_ids 选择的 provider 里能找到，否则整个请求 400。

Playground 能力代理​

浏览器不直连第三方模型服务（CORS / 密钥隔离）。下列接口均由 Manager 按 provider_id 取存库的 base_url + api_key 后转发。请求体需带 provider_id 与 model（ASR 为 multipart form）。

方法路径用途备注
POST/providers/chat/completionsLLM / VLM 对话默认 SSE；VLM 消息可含 image_url；DashScope + Qwen3/QwQ 类会默认 enable_thinking=false 以改善 playground 正文
POST/providers/embeddingsEmbeddingOpenAI 兼容 /embeddings
POST/providers/rerankRerank对 Paratera / llmapi 等优先尝试 /v1/p002/rerank，再回退标准 /rerank
POST/providers/audio/transcriptionsASRmultipart 上传文件；DashScope Qwen-ASR 会转走 chat + input_audio
POST/providers/audio/speechTTS返回音频字节；DashScope 走 Qwen-TTS 原生路径；MiniMax/speech-* 会明确拒绝

约束摘要：

  • model 须属于该 provider 已开启的 models 列表（非空时校验）。
  • provider 须 enabled=true。
  • Realtime / 音色克隆等特殊模型不在上述 HTTP 路径覆盖范围内；由 WebUI 能力评估拦截并提示换模型。
  • WebUI Playground：Embedding / Rerank 文档列表前端最多 10 条（n/10 计数、批量弹窗按行追加）；Rerank 无 Top N 控件，固定对最多前 10 条打分。用户操作说明见手册 Models管理。

部署 / 路由​

  • 容器内监听 8000，由 traefik 通过 PathPrefix(/container) || PathPrefix(/providers) 路由（见 docker-compose.yml 的 nineclaw-manager labels）
  • 前端 vite.config.ts 在 dev 模式把 /providers 代理到 traefik 入口 (http://127.0.0.1:8510)，生产环境同域

修改路由代码后必须 docker compose build nineclaw-manager，单纯 restart 不会 带上新代码（镜像里 COPY 的快照是旧的）。
