RAGFlow 接入说明

NineClaw Manager 可作为 BFF 适配层：前端仍调用现有 /v1/knowledge/* 接口，后端按配置转发到 RAGFlow。

用户侧操作见手册：RAG（知识库）、QYRAG 配置。

配置​

在 NineClaw-Manager/.env 中设置：

KNOWLEDGE_BACKEND=ragflow
RAGFLOW_BASE_URL=http://172.18.33.24:8513
RAGFLOW_API_KEY=<你的 RAGFlow API Key>

API Key 在 RAGFlow 控制台 → 用户设置 → API Keys 中获取。

切换回本地文件存储：

KNOWLEDGE_BACKEND=filesystem

前端​

无需修改前端代码。 WebUI 继续请求 NineClaw Manager（VITE_API_PROXY 或 VITE_API_BASE_URL 指向 Manager 即可）。

接口映射​

NineClaw 前端调用RAGFlow 实际接口
GET/POST/PUT/DELETE /v1/knowledge/api/v1/datasets
POST /v1/knowledge/{id}/filesPOST /api/v1/datasets/{id}/documents
DELETE /v1/knowledge/{id}/files/{docId}DELETE /api/v1/datasets/{id}/documents
POST /v1/datasets/{id}/chunksPOST /api/v1/datasets/{id}/chunks
POST /v1/knowledge/{id}/retrievalPOST /api/v1/retrieval
GET .../preview拉取文档 chunks 拼接 / 下载原文
GET .../files/{docId}/chunks文档切片列表（含 available）
PATCH .../chunks/{chunk_id}单个切片启用/停用 { "available": true/false }
PATCH .../chunks批量切换 { "chunk_ids": [], "available": bool }
GET .../media-content读 RAGFlow 切片 / 可选 ASR 正文（Manager 能力；WebUI 详情预览当前不展示该正文）
POST .../media-transcribe前端切段音轨 → RAGFlow POST .../chat/audio/transcription（可选；WebUI 详情预览当前不调用）
POST /v1/knowledge/qa (SSE)RAGFlow 检索 + Manager 配置的 LLM 流式回答

WebUI 知识库详情页：音视频预览 = 仅播放文件；解析结果通过 切片 查看。Models /providers/audio/transcriptions 与知识库详情预览无关。
Manager 仍保留 media-content / media-transcribe 供兼容或其它调用方使用。

单文档解析状态​

RAGFlow 文档 run 字段映射为详情页文件树展示：

RAGFlow run前端文件状态
DONE已解析
RUNNING解析中
UNSTART待解析
FAIL解析失败

文件列表接口同时返回 RAGFlow 的 progress / progress_msg。WebUI 详情页左侧文件行：默认显示状态 + 大小；鼠标悬停该行时换成进度条，数值随约 3 秒一次的文件列表轮询更新。

知识库卡片状态（库级汇总）​

列表卡片右上角 status 由该库全部文档的 run 汇总得出（API 值 → 界面文案；点/徽章为红绿灯：绿/黄/红）：

API status界面文案汇总规则
pending待构建无文档，或全部仍为未开始
building构建中存在未结束的解析任务
success已就绪全部文档解析成功
part_success部分异常有成功也有失败
fail构建失败全部文档解析失败

兼容旧值：ready→success，indexing→building，failed→fail。

部署检查​

  1. RAGFlow 服务可访问（例如 http://<服务器>:8513）
  2. .env 中 RAGFLOW_API_KEY 已填写；音视频要稳定产出切片时，按交付要求配置 RAGFlow 解析相关模型
  3. 重启 NineClaw Manager 后端
  4. 前端开发：VITE_API_PROXY 指向 Manager 地址
