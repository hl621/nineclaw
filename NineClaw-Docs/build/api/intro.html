概览

API 文档面向需要基于 NineClaw 做集成、调试或二次开发的研发人员。这里集中放置系统中可被调用的接口说明，包括 Manager、WebSearch、Runtime/Hermes 和 QY-RAG 等部分。

如果你只是想学习页面怎么使用，请先看 用户手册；如果你想理解这些接口背后的系统关系，请看 架构设计。

先看哪里​

不同开发目标对应不同 API 入口：

你想做什么建议入口
管理 NineClaw 实例、模型、知识库、Skill、MCP、信源等平台能力Nineclaw Manager
了解 Provider Playground 代理（对话 / Embedding / Rerank / ASR / TTS）Providers API
调用搜索、网页正文抽取、列表链接发现等能力Nineclaw WebSearch
对接 Runtime 的 OpenAI 兼容网关能力Hermes Gateway
管理 Runtime Dashboard 状态和配置Hermes Dashboard
调用 Runtime 内部 WebUI 相关接口Hermes WebUI
查看 QY-RAG / RAGFlow 相关接口QY-RAG

API 分层​

NineClaw 的 API 可以按调用对象理解：

层级说明
Manager API平台管理入口，WebUI 大部分 /v1/* 请求都先进入 Manager
WebSearch API搜索和抽取服务入口，用于信源检索、详情抽取和列表链接发现
Runtime / Hermes API单个 Runtime 实例内部的 Gateway、Dashboard、WebUI 接口
QY-RAG API知识库、文档、检索和 RAGFlow 兼容接口

通常情况下，业务系统优先对接 Manager API；只有在明确知道自己要访问某个 Runtime 实例、搜索服务或 RAG 服务时，才直接查看对应 API 页面。

路径提醒​

部署后，外部访问通常经过 Traefik 统一入口：

能力常见外部路径
Manager/v1/...
WebSearch/ws-api/...
Runtime Gateway/traefik/nineclaw/{instance_id}/gateway/...
Runtime Dashboard/traefik/nineclaw/{instance_id}/dashboard/...
Runtime WebUI/traefik/nineclaw/{instance_id}/webui/...

如果你只关心接口定义，可以直接阅读左侧 API 页面；如果你需要理解路径为什么这样转发，请阅读 Traefik 路由。
