Deploy

NineClaw-Deploy 是 NineClaw 的交付和离线部署项目。它不属于系统运行时业务链路，而是负责把各项目构建、打包，并形成用户可执行的部署包。

面向用户交付时，通常只需要部署包中的 deploy.sh、docker-compose.yml、env.example、docker_images/ 等文件。用户部署时不需要拿到完整开发仓库，也不需要理解每个项目的构建过程。

读图说明​

图中按“构建侧”和“部署侧”区分 Deploy 的职责边界。Deploy 在构建侧收集各项目镜像和 Compose 配置，产出离线部署包；用户在部署侧执行脚本启动系统。系统启动后，业务流量不会再进入 Deploy。

模块关系​

相关模块联系
WebUIDeploy 打包 WebUI 镜像，并在 Compose 中配置 / 路由
DocsDeploy 打包 Docs 镜像，并在 Compose 中配置 /docs 路由
ManagerDeploy 打包 Manager 镜像，并配置 /v1 和直连端口
RuntimeDeploy 准备 Runtime 镜像；实际实例由 Manager 在运行时创建
WebSearchDeploy 打包 WebSearch 镜像，并配置 /ws-api 路由
PostgreSQL / TraefikDeploy 在 Compose 中定义基础服务、端口和网络关系

交付物边界​

用户侧实际需要的是部署包，而不是构建仓库。部署包通常包含：

文件或目录作用
deploy.sh安装、卸载、导入镜像、启动服务等交互式入口
docker-compose.yml定义 Traefik、Docs、WebUI、Manager、WebSearch、PostgreSQL 等服务
env.example部署参数模板，用于生成或修改 .env
docker_images/离线镜像包，供目标机器导入

构建侧可能存在 build.sh、codes/、构建日志等内容，但这些属于发布制品生成过程，不是普通用户部署 NineClaw 时必须理解或使用的内容。

用户部署流程​

用户拿到部署包后，典型流程如下：

  1. 拷贝部署包到目标机器。
  2. 根据 env.example 生成或修改 .env。
  3. 执行 deploy.sh。
  4. 导入 docker_images/ 中的离线镜像。
  5. 检查或创建 qiyuan_net。
  6. 通过 docker-compose.yml 启动固定服务。
  7. 用户通过 http://<TRAEFIK_HOST>:8510 访问系统。

和运行时系统的关系​

Deploy 负责“把系统启动起来”，但系统运行后的访问链路不经过 Deploy：

阶段主要参与者说明
交付前Deploy构建镜像、整理 Compose、生成离线部署包
安装时Deploy 脚本、Docker、Compose导入镜像、创建网络、启动固定服务
运行时Traefik、WebUI、Docs、Manager、WebSearch、PostgreSQL、Runtime承载用户访问和业务流程

因此架构图中 Deploy 应放在运行时系统之外，作为独立交付层，而不是放在 WebUI、Manager、Runtime 之间的业务调用链中。
