Traefik 路由

Traefik 是 NineClaw 生态的统一访问入口。它负责把外部请求按路径前缀转发到 WebUI、Docs、Manager、WebSearch 以及动态创建的 NineClaw-Runtime 实例。

路由职责​

NineClaw 中的 Traefik 主要承担两类职责：

职责说明
固定服务挂载WebUI、Docs、Manager、WebSearch 等基础服务在 docker-compose.yml 中声明 Traefik labels
Runtime 实例路由Manager 创建 NineClaw-Runtime 实例容器时，动态写入 Traefik labels，让实例自动挂载到统一入口

Traefik 通过 Docker Provider 监听 Docker Socket，发现带有 traefik.enable=true 的容器，并根据容器 labels 自动生成路由。

固定服务路由​

部署包中的 docker-compose.yml 会为基础服务配置固定路由：

服务Traefik 路由中间件容器端口内部路径变化
nineclaw-webuiPathPrefix(/)无80原路径转发
nineclaw-docsPathPrefix(/docs)无3000原路径转发
nineclaw-managerPathPrefix(/v1)无8000原路径转发
nineclaw-websearchPathPrefix(/ws-api)strip /ws-api，add /v18000/ws-api/search -> /v1/search
opensandbox-serverPathPrefix(/sandbox)无8090原路径转发

这些服务随系统启动，由 Compose 和 Traefik 自动挂载。

其中 WebSearch 是固定路由里唯一会改写路径的服务：

外部: http://<host>:8510/ws-api/search
Traefik: 去掉 /ws-api，再补上 /v1
内部: http://nineclaw-websearch:8000/v1/search

Manager 的 /v1 不会被 strip。因此：

外部: http://<host>:8510/v1/health
内部: http://nineclaw-manager:8000/v1/health

Docs 和 OpenSandbox 也是原路径转发：

外部: http://<host>:8510/docs/...
内部: http://nineclaw-docs:3000/docs/...

外部: http://<host>:8510/sandbox/...
内部: http://opensandbox-server:8090/sandbox/...

Runtime 实例路由​

每个 NineClaw-Runtime 实例由 Manager 创建和管理。创建实例时，Manager 会为实例容器写入 Traefik labels，把实例内部端口挂到统一入口下。

每个实例包含三个主要服务：

Runtime 服务容器端口路由路径中间件转发示例
Gateway8642/traefik/nineclaw/{instance_id}/gateway/CORS、stripPrefix、注入 Authorization/gateway/health -> /health
WebUI8643/traefik/nineclaw/{instance_id}/webui/CORS、stripPrefix/webui/api/sessions -> /api/sessions
Dashboard8644/traefik/nineclaw/{instance_id}/dashboard/CORS、stripPrefix、注入 Authorization/dashboard/api/status -> /api/status

示例：

curl http://localhost:8510/traefik/nineclaw/a1b2c3d4/gateway/
open http://localhost:8510/traefik/nineclaw/a1b2c3d4/webui/
curl http://localhost:8510/traefik/nineclaw/a1b2c3d4/dashboard/

标签生成机制​

Manager 创建 Runtime 容器时，会按服务类型生成 Traefik labels。核心逻辑来自 Manager 的 Runtime 拓扑配置：Gateway、WebUI、Dashboard 分别对应 8642、8643、8644。

配置作用
traefik.http.routers.*.rule使用 PathPrefix 匹配外部访问路径
traefik.http.routers.*.entrypoints指向 Traefik 的 Web 入口
traefik.http.services.*.loadbalancer.server.port指向 Runtime 容器内部端口
traefik.http.middlewares.*.stripprefix.prefixes转发前去除外部路径前缀
traefik.http.middlewares.*.headers.customrequestheaders.Authorization需要鉴权的 Runtime 服务由 Traefik 注入 token

Runtime 实例的路由前缀由 Manager 配置控制：

NINECLAW_ROUTE_GATEWAY=/traefik/nineclaw/{instance_id}/gateway
NINECLAW_ROUTE_WEBUI=/traefik/nineclaw/{instance_id}/webui
NINECLAW_ROUTE_DASHBOARD=/traefik/nineclaw/{instance_id}/dashboard

生成后的效果可以理解为：

服务Traefik serviceloadbalancer.server.portstripPrefix.prefixes
Gatewaynineclaw-{id}-gateway8642/traefik/nineclaw/{id}/gateway/
WebUInineclaw-{id}-webui8643/traefik/nineclaw/{id}/webui/
Dashboardnineclaw-{id}-dashboard8644/traefik/nineclaw/{id}/dashboard/

路径前缀处理​

Runtime 路由会使用 stripPrefix 中间件。外部访问路径进入 Traefik 后，Traefik 会去除实例路由前缀，再转发到容器内部服务。

例如：

外部请求转发到 Runtime 内部
/traefik/nineclaw/a1b2c3d4/gateway/status/status
/traefik/nineclaw/a1b2c3d4/dashboard/api/status/api/status

这样 Runtime 内部服务不需要感知外部挂载路径。

网络要求​

Traefik、Manager、WebUI、Docs、WebSearch、PostgreSQL 以及所有 Runtime 实例都需要连接到同一个 Docker 网络：

docker network create qiyuan_net

在部署脚本中，deploy.sh 会检查并创建 qiyuan_net。Runtime 实例创建时也会加入该网络，以便 Traefik 能直接转发请求到实例容器。

排查方向​

当路由不可访问时，优先检查以下方向：

问题排查方式
Traefik 未发现容器检查容器是否带有 traefik.enable=true label
Runtime 路由未出现检查 Manager 创建实例时写入的 Traefik labels
路径访问 404检查 Manager 中的 NINECLAW_ROUTE_* 配置是否与容器 labels 一致
容器不可达检查容器是否运行中，并确认已加入 qiyuan_net
转发后路径异常检查 stripPrefix 中间件配置

常用命令：

docker compose logs -f traefik
docker inspect <container_id> --format='{{json .Config.Labels}}'
docker inspect <container_id> --format='{{json .NetworkSettings.Networks}}'

Traefik Dashboard 默认地址：

http://<TRAEFIK_HOST>:8511
