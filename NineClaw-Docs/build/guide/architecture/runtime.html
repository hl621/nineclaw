Runtime

NineClaw-Runtime 基于 Hermes 改造，是 NineClaw 实例的实际运行环境。部署包中的 nineclaw-runtime 服务主要用于构建 Runtime 镜像；真正运行时，Runtime 实例由 Manager 按需创建。

每个 Runtime 实例会作为独立容器运行，并通过 Traefik 暴露 Gateway、WebUI、Dashboard 三类入口。外部用户、WebUI 和 Manager 都不应该直接访问 Runtime 容器 IP，而是通过 Traefik 的实例路由进入。

读图说明​

图中展示一个 Runtime 实例被访问时的路由链路。Traefik 是实例访问的唯一入口；Runtime 内部的 Gateway、WebUI、Dashboard 通过不同端口承载不同能力，外部路径进入后会先经过 stripPrefix 再转发到内部服务。

模块关系​

相关模块联系
ManagerManager 创建和管理 Runtime 实例，并写入 Traefik labels
TraefikTraefik 根据 labels 自动生成实例路由
WebUIWebUI 使用 Manager 返回的实例访问地址进入 Runtime
Docker SocketManager 通过 Docker API 创建 Runtime 容器
qiyuan_netRuntime 必须加入该网络，Traefik 才能转发请求到实例容器

实例端口​

每个 Runtime 实例包含三个内部服务端口：

Runtime 服务容器端口Traefik 路由说明
Gateway8642/traefik/nineclaw/{instance_id}/gateway/Runtime 对外服务网关
WebUI8643/traefik/nineclaw/{instance_id}/webui/实例内部 WebUI
Dashboard8644/traefik/nineclaw/{instance_id}/dashboard/Runtime 管理和状态 API

这三个端口是 Runtime 容器内部端口，不需要直接映射到宿主机。外部访问统一走 8510，由 Traefik 按实例 ID 和路径前缀转发。

Manager 写入的 Traefik labels 会把三类路径分别指向三个内部端口：

外部路径前缀Traefik serviceRuntime 内部端口主要中间件
/traefik/nineclaw/{id}/gateway/nineclaw-{id}-gateway8642CORS、stripPrefix、注入 Authorization
/traefik/nineclaw/{id}/webui/nineclaw-{id}-webui8643CORS、stripPrefix
/traefik/nineclaw/{id}/dashboard/nineclaw-{id}-dashboard8644CORS、stripPrefix、注入 Authorization

实例创建后的路由形态​

假设实例 ID 为 demo，部署机器地址为 192.168.1.10，实例创建后会形成以下访问地址：

目标外部访问地址
Gatewayhttp://192.168.1.10:8510/traefik/nineclaw/demo/gateway/
WebUIhttp://192.168.1.10:8510/traefik/nineclaw/demo/webui/
Dashboardhttp://192.168.1.10:8510/traefik/nineclaw/demo/dashboard/

路径转发时，Traefik 会去除实例前缀。例如：

外部请求转发到 Runtime 内部
/traefik/nineclaw/demo/gateway/status/status
/traefik/nineclaw/demo/webui//
/traefik/nineclaw/demo/dashboard/api/status/api/status

Gateway 和 Dashboard 路由需要访问 Runtime 内部 API，Traefik 会按 Manager 写入的 labels 注入 Authorization: Bearer <NINECLAW_TOKEN>。

因此三条完整链路分别是：

http://<host>:8510/traefik/nineclaw/demo/gateway/status
  -> traefik:80
  -> strip /traefik/nineclaw/demo/gateway/
  -> nineclaw-demo:8642/status

http://<host>:8510/traefik/nineclaw/demo/webui/api/sessions
  -> traefik:80
  -> strip /traefik/nineclaw/demo/webui/
  -> nineclaw-demo:8643/api/sessions

http://<host>:8510/traefik/nineclaw/demo/dashboard/api/status
  -> traefik:80
  -> strip /traefik/nineclaw/demo/dashboard/
  -> nineclaw-demo:8644/api/status

和 Manager 的协作​

Runtime 本身不负责把自己注册到 Traefik。实例路由由 Manager 在创建容器时写入 labels，再由 Traefik 的 Docker Provider 自动发现。也就是说，Runtime 能被访问依赖三个条件同时成立：

条件说明
容器运行中Manager 成功创建并启动 Runtime 容器
加入 qiyuan_netTraefik 能在容器网络内访问 Runtime
labels 正确Traefik 能识别实例路径、内部端口和中间件

如果实例容器存在但访问 404，通常优先检查 labels 和 Traefik Dashboard；如果路由存在但请求超时，优先检查容器是否加入 qiyuan_net 以及内部端口是否正常。

和 Compose 的关系​

docker-compose.yml 中的 nineclaw-runtime 不是安装后默认常驻的业务容器，它用于构建 Runtime 镜像。用户创建实例后，Manager 才会基于该镜像创建实际运行的实例容器。
