Manager

NineClaw-Manager 是系统的业务管理层，容器内部端口为 8000。它通过 Traefik 的 /v1 路由服务 WebUI，同时通过 Docker API 管理 Runtime 实例容器。

Manager 的核心价值是把分散的基础能力组织成稳定的产品接口：前端只调用 Manager，Manager 再向下管理 Runtime，向侧面适配 QY-RAG/RAGFlow、WebSearch、OpenSandbox，并把业务状态写入 PostgreSQL。

读图说明​

图中按泳道展示 Runtime 创建流程。这个流程同时跨越 WebUI、Manager、PostgreSQL、Docker、Traefik、Runtime 六个参与方，重点不是“调用了一个接口”，而是 Manager 需要同时完成业务状态、容器生命周期和访问路由三件事。

模块关系​

相关模块联系
WebUIWebUI 调用 Manager 的 /v1 接口完成业务操作
TraefikManager 自身挂载到 /v1，同时写入 Runtime 容器 labels 让 Traefik 自动发现实例路由
RuntimeManager 负责创建、启动、停止、重启、删除 Runtime 实例
PostgreSQLManager 使用 nineclaw_manager 数据库存储实例、配置、状态等信息
Docker SocketManager 通过 Docker API 操作容器、网络和 labels
QY-RAG/RAGFlowManager 对 RAG 能力做二次包装，向前端提供统一知识库接口
WebSearchManager 维护 WebSearch 相关配置和调用入口
OpenSandboxManager 在需要沙箱能力时调用 OpenSandbox

对外入口​

Manager 有两个访问入口：

入口用途
http://<TRAEFIK_HOST>:8510/v1WebUI 和外部调用的主入口，推荐通过 Traefik 访问
http://<TRAEFIK_HOST>:${API_PORT:-8080}Manager 直连端口，默认 8080，主要用于部署排查

日常用户链路应走 Traefik 的 /v1。直连端口用于确认 Manager 本身是否可用，避免把 Traefik 路由问题和 Manager 服务问题混在一起排查。

Runtime 生命周期管理​

Runtime 生命周期是 Manager 最关键的职责。创建实例时，Manager 会把“业务实例”和“容器路由”同时建立起来：

  1. 接收 WebUI 发起的创建实例请求。
  2. 校验请求参数，准备实例名称、镜像、环境变量、token、路由前缀等配置。
  3. 在 nineclaw_manager 数据库中写入实例记录和初始状态。
  4. 调用 Docker API 创建 Runtime 容器。
  5. 将 Runtime 容器加入 qiyuan_net。
  6. 为容器写入 Traefik labels，包括 PathPrefix、内部端口、stripPrefix、鉴权请求头等。
  7. 启动 Runtime 容器。
  8. Traefik 通过 Docker Provider 自动发现 labels 并生成实例路由。
  9. Manager 更新实例状态，并把 Gateway、WebUI、Dashboard 地址返回给 WebUI。

停止、重启、删除实例时，Manager 同样需要同步容器状态和数据库状态，避免出现“数据库显示运行但容器已不存在”或“容器仍在运行但页面不可见”的状态漂移。

内部访问方式​

Manager 在容器网络内访问 Traefik 使用：

TRAEFIK_INTERNAL_URL=http://traefik:80

这样 Manager 可以通过 Traefik 访问 Runtime Dashboard、Gateway 等服务，而不需要直接依赖 Runtime 容器 IP。这个设计让 Runtime 实例的访问方式和外部用户访问方式保持一致，都由 Traefik 负责路由匹配和路径转换。

例如 Manager 访问某个 Runtime Dashboard 状态接口时，链路是：

nineclaw-manager
  -> http://traefik:80/traefik/nineclaw/{instance_id}/dashboard/api/status
  -> Traefik strip /traefik/nineclaw/{instance_id}/dashboard/
  -> nineclaw-{instance_id}:8644/api/status

Manager 创建 Runtime 容器时，也会把以下端口和路径关系写入 labels：

Runtime 服务外部路径前缀Runtime 内部端口是否注入 Authorization
Gateway/traefik/nineclaw/{id}/gateway/8642是
WebUI/traefik/nineclaw/{id}/webui/8643否
Dashboard/traefik/nineclaw/{id}/dashboard/8644是

状态与配置​

Manager 持久化的数据主要包括：

类型示例
Runtime 实例状态实例 ID、容器名、镜像、运行状态、访问地址
系统配置模型供应商、MCP Server、Skills、默认参数
RAG 适配信息知识库、数据集、任务映射或外部 RAGFlow 配置
WebSearch 配置搜索服务入口、开关、策略参数

这些数据属于 Manager 的业务状态，不应由 WebUI、Runtime 或 WebSearch 直接写入。

职责边界​

Manager 不承载前端页面，不直接执行搜索任务，也不作为 Runtime 内部业务进程。它的边界是“系统编排和统一 API”：把容器、路由、数据库、RAG、搜索、沙箱等能力组织成前端可用的业务接口。
