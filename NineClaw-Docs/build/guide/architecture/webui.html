WebUI

NineClaw-WebUI 是用户进入 NineClaw 的主要界面。它通过 Traefik 的 / 路由对外提供访问，容器内部端口为 80。

WebUI 的定位是“用户操作入口”，不是业务编排层。它不直接管理 Runtime 容器，不直接访问 PostgreSQL，也不直接拼接容器内部地址。前端只面向统一入口下的路径发起请求，再由 Traefik 和 Manager 完成服务发现、路由转换和实例管理。

读图说明​

图中按泳道展示 WebUI 参与的典型用户流程：用户先访问统一入口拿到前端页面，随后不同功能会走不同路径。普通业务配置、实例管理、RAG 管理走 Manager；搜索任务走 WebSearch；Runtime 实例页面则走 Manager 返回的实例路由。

模块关系​

相关模块联系
TraefikWebUI 通过 / 路由挂到统一入口 8510；前端对外暴露地址也以该入口为准
ManagerWebUI 调用 /v1 下的管理接口，完成实例、RAG、Skills、MCP、Provider 等操作
WebSearchWebUI 通过 /ws-api 访问搜索服务，由 Traefik 完成路径转换
RuntimeWebUI 不直接创建 Runtime；实例访问地址由 Manager 返回，最终通过 Traefik 进入实例
DocsDocs 与 WebUI 共享同一个 Traefik 入口，Docs 位于 /docs

前端请求入口​

WebUI 面向用户展示统一界面，但它背后会根据功能把请求分到不同入口：

功能区域外部路径后端模块说明
首页和应用界面/nineclaw-webuiTraefik 转发到 WebUI 容器内部 80 端口
实例管理/v1nineclaw-manager创建、启动、停止、删除 Runtime 实例
RAG 模块/v1nineclaw-managerManager 对 QY-RAG/RAGFlow 做二次包装
WebSearch 模块/ws-apinineclaw-websearchWebSearch 独立处理搜索和内容抽取任务
Runtime 实例/traefik/nineclaw/{instance_id}/...nineclaw-{instance_id}访问实例 Gateway、WebUI、Dashboard
文档入口/docsnineclaw-docs跳转到文档站点

典型流程​

打开系统首页​

用户访问：

http://<TRAEFIK_HOST>:8510/

请求会先进入 Traefik，再转发到 WebUI 容器内部 80 端口。这个过程只负责加载前端页面，不会触发 Runtime 实例创建。

创建 Runtime 实例​

用户在 WebUI 中创建实例时，WebUI 会调用 Manager 的 /v1 接口。Manager 负责写入实例状态、调用 Docker API 创建 Runtime 容器、写入 Traefik labels，并把实例访问地址返回给 WebUI。

WebUI 在这个流程中只负责提交请求和展示状态，不负责决定容器名称、内部端口、网络连接和 Traefik labels。

使用 WebSearch​

用户在 WebUI 中发起搜索时，请求走：

http://<TRAEFIK_HOST>:8510/ws-api

Traefik 会把 /ws-api 转换为 WebSearch 内部的 /v1 前缀，再转发给 WebSearch。WebUI 不直接感知 WebSearch 容器内部地址。

设计边界​

WebUI 应保持轻量：它负责用户交互、状态展示和调用统一 API，不负责持久化、不直接调用 Docker、不直接管理 Runtime 网络。这样可以把部署差异收敛到 Traefik、Manager 和 Compose 配置中，避免前端依赖具体容器拓扑。
