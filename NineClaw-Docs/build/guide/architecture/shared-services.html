系统依赖关系

NineClaw 部署后有一组系统级依赖。它们不是某个单独业务模块的一部分，但多个模块都依赖它们正常工作。

这些依赖包括 PostgreSQL、qiyuan_net、Docker Socket、OpenSandbox 和 skills_storage 等。它们的共同特点是：不直接面向最终用户，但一旦配置错误，会影响多个模块。沙箱的业务意义和解耦方式请阅读 SandBox。

读图说明​

图中从左到右展示业务服务、共享依赖和故障影响面。重点不是一次调用链，而是当 PostgreSQL、qiyuan_net、Docker Socket、skills_storage 或 OpenSandbox 出问题时，哪些模块会同时受影响。

需要特别注意三点：

依赖说明
PostgreSQL是一个 postgres 容器，里面初始化 nineclaw_manager 和 nineclaw_websearch 两个库，不是两个独立数据库容器
Docker Socket不只 Manager 使用，Traefik 也依赖它发现带有 labels 的容器，OpenSandbox 也依赖它调度沙箱执行
qiyuan_net固定服务和 Runtime 实例都需要加入这个网络，Traefik 才能把请求转发到对应容器

PostgreSQL​

PostgreSQL 是系统共享数据库，宿主机端口为 15432，容器内部端口为 5432。

部署时会创建至少两个数据库：

数据库使用方说明
nineclaw_managerNineClaw-Manager保存实例、系统配置、RAG 适配、Provider、MCP 等数据
nineclaw_websearchNineClaw-WebSearch保存搜索任务、结果、缓存或内容抽取数据

PostgreSQL 不属于某一条单独业务调用链，而是为 Manager 和 WebSearch 等服务提供持久化能力。业务排查时需要先区分问题属于 Manager 业务库还是 WebSearch 搜索库。

qiyuan_net​

所有核心服务连接到同一个 Docker 网络：

qiyuan_net

该网络中至少包含：

容器说明
traefik统一入口和服务发现
nineclaw-webui前端
nineclaw-docs文档站点
nineclaw-manager后端管理服务
nineclaw-websearch聚合搜索服务
opensandbox-server沙箱执行服务
postgresPostgreSQL 数据库
nineclaw-{instance_id}Manager 动态创建的 Runtime 实例

Runtime 实例必须加入 qiyuan_net，否则 Traefik 无法把请求转发到实例容器。固定服务也应加入该网络，保证 Traefik 能够通过容器名和内部端口访问它们。

Docker Socket​

Manager 和 OpenSandbox 都会访问 Docker Socket。

使用方用途
Manager创建 Runtime 容器、写入 labels、加入网络、启动停止实例
OpenSandbox提供沙箱执行相关容器能力

Docker Socket 代表较高权限，因此部署环境需要确保这些服务运行在可信环境中，并避免把 Docker 控制能力暴露给不可信调用方。

OpenSandbox​

OpenSandbox 服务通过 /sandbox 路由挂到 Traefik，容器内部端口为 8090。它为系统提供沙箱执行相关能力，并由 Manager 在需要时调用。

OpenSandbox 属于系统能力支撑层，不负责前端页面、Runtime 生命周期或搜索任务。更完整的沙箱设计请阅读 SandBox。

skills_storage​

skills_storage 用于保存 Skills 相关持久化内容。它与 Manager 的技能管理能力相关，避免容器重启后技能文件或配置丢失。

排查建议​

系统依赖出问题时，通常会表现为多个模块同时异常：

现象优先检查
WebUI 能打开但实例无法访问Runtime 是否加入 qiyuan_net，Traefik 是否发现实例 labels
Manager 接口异常或状态丢失nineclaw_manager 数据库连接和迁移状态
搜索任务失败或结果为空WebSearch 服务日志和 nineclaw_websearch 数据库
Runtime 无法创建Manager 是否能访问 Docker Socket，Runtime 镜像是否存在
沙箱能力不可用OpenSandbox 服务状态和 Docker Socket 权限
