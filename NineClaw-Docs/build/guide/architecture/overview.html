系统架构

简介页中的总体关系用于说明 NineClaw 生态各项目之间的职责边界。本页从部署视角说明系统的整体结构、端口和路由入口。每个模块和其他模块的联系、关键流程，会在本节后续页面中分别展开。

NineClaw 部署后以 Traefik 作为统一入口。WebUI、Docs、Manager、WebSearch、OpenSandbox 等固定服务通过 docker-compose.yml 挂载到 Traefik；NineClaw-Runtime 实例由 NineClaw-Manager 动态创建，实例路由由 Manager 写入容器 labels 后被 Traefik 自动发现。

整体结构​

从部署形态看，NineClaw 可以分成四层：

层级组件说明
访问入口traefik对外暴露统一入口 8510，按路径转发到各个服务
产品服务nineclaw-webui、nineclaw-docs、nineclaw-manager、nineclaw-websearch、opensandbox-server安装后常驻运行，构成用户可访问的主体功能和沙箱执行支撑
运行实例nineclaw-{instance_id}由 Manager 按需创建的 Runtime 实例，不是 Compose 中默认常驻的业务容器
系统依赖postgres、qiyuan_net、Docker Socket、skills_storage为多个服务提供数据库、网络、容器管理和持久化能力

部署包中的 docker-compose.yml 还包含 nineclaw-sandbox、nineclaw-runtime 两个 build profile 服务。它们用于构建镜像，不代表安装后会固定启动同名业务容器。实际 Runtime 实例由 Manager 根据用户操作动态创建。

端口与路由总览​

对外暴露的宿主机端口以部署包中的 docker-compose.yml 为准：

宿主机端口映射目标说明
8510Traefik :80NineClaw 统一 HTTP 入口，WebUI、Docs、Manager、WebSearch、Runtime 实例都通过该入口访问
8511Traefik :8080Traefik Dashboard，用于查看路由、服务和中间件状态
15432PostgreSQL :5432数据库端口，主要用于部署调试或运维连接
${API_PORT:-8080}NineClaw-Manager :8000Manager API 直连端口，默认 8080，主要用于运维排查

用户侧主要访问 8510。进入 Traefik 后，Traefik 会根据路径前缀把请求转发到不同容器。固定服务的映射关系如下：

外部访问Traefik 规则中间件容器目标转发后的内部路径
http://<host>:8510/PathPrefix(/)无nineclaw-webui:80原路径不改写，例如 /
http://<host>:8510/docs/...PathPrefix(/docs)无nineclaw-docs:3000原路径不改写，例如 /docs/...
http://<host>:8510/v1/...PathPrefix(/v1)无nineclaw-manager:8000原路径不改写，例如 /v1/...
http://<host>:8510/ws-api/searchPathPrefix(/ws-api)strip /ws-api，再 add /v1nineclaw-websearch:8000/v1/search
http://<host>:8510/sandbox/...PathPrefix(/sandbox)无opensandbox-server:8090原路径不改写，例如 /sandbox/...

/ 是 WebUI 的兜底入口；/docs、/v1、/ws-api、/sandbox 等更具体的路径会优先匹配到对应服务。

Runtime 实例创建后，会额外挂载实例级路由。实例路由不是写在 Compose 固定服务里，而是 Manager 创建 Runtime 容器时通过 Docker labels 动态写入：

外部访问Traefik 规则中间件Runtime 容器目标转发后的内部路径
/traefik/nineclaw/{id}/gateway/statusPathPrefix(/traefik/nineclaw/{id}/gateway/)CORS、stripPrefix、注入 Authorizationnineclaw-{id}:8642/status
/traefik/nineclaw/{id}/webui/api/sessionsPathPrefix(/traefik/nineclaw/{id}/webui/)CORS、stripPrefixnineclaw-{id}:8643/api/sessions
/traefik/nineclaw/{id}/dashboard/api/statusPathPrefix(/traefik/nineclaw/{id}/dashboard/)CORS、stripPrefix、注入 Authorizationnineclaw-{id}:8644/api/status

Manager 在容器网络内访问 Runtime 也走 Traefik，默认内部入口是：

TRAEFIK_INTERNAL_URL=http://traefik:80

因此 Manager 访问某个 Runtime Dashboard API 时，实际链路是：

nineclaw-manager
  -> http://traefik:80/traefik/nineclaw/{id}/dashboard/api/...
  -> nineclaw-{id}:8644/api/...

访问示例​

假设部署机器地址为 192.168.1.10：

目标地址
WebUIhttp://192.168.1.10:8510/
Docshttp://192.168.1.10:8510/docs
Manager APIhttp://192.168.1.10:8510/v1
WebSearch APIhttp://192.168.1.10:8510/ws-api
Traefik Dashboardhttp://192.168.1.10:8511
Manager API 直连http://192.168.1.10:8080

Runtime 实例创建后，可通过实例 ID 访问：

http://192.168.1.10:8510/traefik/nineclaw/{instance_id}/gateway/
http://192.168.1.10:8510/traefik/nineclaw/{instance_id}/webui/
http://192.168.1.10:8510/traefik/nineclaw/{instance_id}/dashboard/
