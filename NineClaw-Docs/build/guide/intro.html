总览

NineClaw 是一个面向组织的 AI 集成与运行平台。它把模型、知识库、搜索、智能体、工具、离线部署和 API 接口组织到一起，让业务研发团队拥有一套可复用的通用组件。

这些组件就像积木：新项目需要知识库、搜索、工具调用、模型接入或离线部署时，不必每次从零搭一遍。团队可以直接复用已有能力，加快研发进度，减少重复造轮子，也更容易把客户已有系统接进来。

你可以把这页当成文档地图：想理解 NineClaw 为什么这么做，看 产品介绍；想知道系统怎么搭起来，看 架构设计；想学习怎么使用，看 用户手册；想部署系统，看 系统部署；想开发 NineClaw 系统，看 协同开发；想基于系统做研发，看 API。

如果你还不熟悉 RAG、Runtime、Skill、MCP 这些词，也没关系。先把它们理解成“知识库能力”“智能体运行环境”“可复用技能”“外部工具接入方式”即可，后面的章节会逐步展开。

先看大局​

如果你只想先建立一个整体印象，可以先抓住这几件事：

你想知道简短回答去哪里看细节
NineClaw 为什么这样设计它服务的是组织级 AI 建设，重点是复用组件、接入系统、支撑研发产品介绍

开发者怎么接入看 API 文档，里面包含当前系统可被利用的接口API

它提供什么能力​

NineClaw 不是把所有能力都写在一个项目里，而是把不同能力统一接起来：

能力用来做什么去哪里看细节
模型管理接入和管理不同的大模型，例如私有模型、OpenAI 兼容模型等模型接口
知识问答把文档变成可检索、可问答、可追溯来源的知识能力知识问答
信源管理把内网搜索、文档门户、业务系统查询等接成统一搜索入口信源管理
Runtime 实例提供智能体运行环境，让工具调用和任务执行真正跑起来Runtime 架构
Skill 创建把常用操作沉淀成可复用技能，后续项目直接拿来用技能创建
MCP / Skill 部署把外部工具或内部技能部署进系统，供智能体或业务系统调用批量部署
离线部署把镜像、Compose、环境配置打包交付到内网环境系统部署

什么场景下用​

NineClaw 更适合有“平台化”和“工程化”需求的场景：

场景NineClaw 能帮什么
企业或机构内网环境支持私有模型、离线部署、内网知识库和内部信源接入
驻场研发项目把共性能力沉淀下来，减少每个项目重复造轮子
知识库增强应用把文档资料变成可问答、可检索、能看到来源的能力
多系统信息汇聚把搜索门户、文档平台、业务系统接口纳入统一搜索入口
智能体工具调用让智能体可以调用知识库、搜索、技能和外部工具完成任务
多厂商协作通过开放接口和接入规范，让不同团队的能力能一起服务客户
基于 AI 做二次开发通过 API、Runtime 和部署能力，把 AI 嵌入已有业务系统

如果你只是想找一个轻量聊天工具，NineClaw 可能不是最轻的选择。它更适合要做私有化部署、系统集成、知识库建设、工具复用和二次开发的团队。

解决什么问题​

NineClaw 主要解决组织落地 AI 时的工程问题：

问题NineClaw 的解法去哪里看细节
AI 能力分散用统一界面和后端管理模型、知识库、搜索、运行时、技能和工具Manager 架构
内网部署麻烦用 NineClaw-Deploy 组织镜像、Compose、离线包和服务更新Deploy 架构
搜索能力离线后失效用 WebSearch 接入内网信源，让 Agent 继续能搜索和抽取信息WebSearch 架构
知识库只会简单检索使用 QY-RAG 的召回与重排能力，并在外层组织问答链路知识问答
工具能力难复用通过技能、MCP 和运行时形成可部署、可调用的工具能力批量部署
接口对接不清楚API 文档集中放置系统可利用接口API
