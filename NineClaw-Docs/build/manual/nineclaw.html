NineClaw

NineClaw 页面用于管理 Runtime 实例（对话运行环境），不是 deploy.sh 里的平台容器。平台服务启停见 运维管理；两层区别见 概览。

各资源页面可先把能力 配置 进平台；实例 运行中 后，再在对应页面 部署 或在创建向导中勾选。

首次使用建议按 系统部署 — 初始化步骤 操作：添加模型 → 创建实例 → 部署模型到实例 → 对话验证。

访问地址示例：http://xxx:8510/nineclaw

进入页面​

  1. 打开 NineClaw WebUI（默认端口 8510）。
  2. 在左侧导航 系统配置 下点击 NineClaw。
  3. 页面以卡片形式展示当前已有实例。

页面上能看到什么​

区域说明
状态筛选顶部显示「全部状态」及实例总数
搜索框按实例名称搜索，例如输入 测试
+ 创建右上角紫色按钮，新建 Runtime 实例
实例卡片展示名称、运行状态、执行次数、镜像版本等
卡片快捷操作鼠标悬停时：可出现 启动 / 停止（图标随状态切换）及重启等；编辑在 ⋮ 菜单内（「链接」上方）
卡片菜单 ⋮启动、停止、重启、编辑、删除、打开链接等

实例卡片上的状态很重要：

状态含义
创建中实例正在创建，容器尚未就绪，请稍候
初始化服务容器已创建，正在初始化 Runtime 及相关服务
运行中实例可正常使用，可打开 WebUI 对话
已停止实例已关闭；需先启动才能进入详情或对话

已停止的实例不能进入详情页。 若点击被提示「请先启动」，请先用悬停区的 启动 或 ⋮ → 启动，等到 运行中 再进入。

卡片上还显示镜像版本（如 nineclaw:v2026.6.19）和托管类型（如「无端托管」）。后续部署资源或打开对话时，通常需要选择 运行中 的实例。

创建实例​

点击右上角 + 创建，按向导分四步完成配置。

步骤是否必填说明
1 容器配置必填填写名称、内存、CPU
2 模型配置视情况若下拉框有可选模型，选择主模型；若为空，见下方说明
3 业务资产可选不勾选任何 Skill / MCP，可直接点 下一步
4 外部资源可选不勾选任何 RAG / WebSearch，可直接点 创建

快速创建： 若暂时不需要 Skill、MCP、知识库和搜索信源，步骤 3、4 保持默认（已选 0 项）即可一路点 下一步 → 创建，后续随时再补充配置。

创建前请确认 Runtime 镜像已导入。 Manager 会按环境变量 NINECLAW_IMAGE（示例：nineclaw:v2026.7.7.2）拉取本地镜像创建容器。若部署机上没有该标签，创建会失败并提示「Docker 镜像不存在」。处理方式见下方 常见排查。

步骤 1：容器配置​

填写实例名称和基础资源限制。

字段说明
名称实例展示名，建议能体现用途，例如 研发助手
内存分配给该实例的最大内存，例如 4G
CPU分配给该实例的 CPU 核数，例如 2

填写完成后点击 下一步。

创建前请确认服务器剩余资源足够。内存和 CPU 设置过低可能导致实例启动失败或运行缓慢。

步骤 2：模型配置​

若 Models 页面已添加模型供应商，下拉框会列出可选的 主模型。

操作说明
选择 主模型例如 Kimi / kimi-k2.5，实例对话默认使用该模型
辅助模型配置（可展开）为视觉理解、网页抽取等任务单独指定模型；不修改则显示 跟随主模型
点击 下一步已选主模型或暂时跳过后均可继续

如果下拉列表为空：

  1. 先到 Models管理 点击 + 添加，保存至少一个供应商；
  2. 完成本向导后续步骤，创建实例并等待 运行中；
  3. 回到 Models 页面点击 部署，把模型部署到该实例（详见 系统部署 — 初始化第 4 步）。

实例能正常对话，以 Models 页面 部署完成 为准，不一定非要在本步骤选定主模型。

步骤 3：业务资产（可跳过）​

按需勾选实例需要的 Skill 和 MCP。

本步可以完全跳过： 左侧 Skill、右侧 MCP 都不勾选（保持「已选 0/x」），直接点击右下角 下一步 即可进入步骤 4。界面上的说明也写了：「这些能力可以跳过，后续仍可继续部署或调整。」

区域说明
左侧 Skill需要时再勾选；搜索框可快速查找
右侧 MCP需要时再勾选；搜索框可快速查找
全选一键选中当前列表全部项（非必须）
下一步无论是否勾选，都可以点击继续

相关手册：

  • Skill（技能库）
  • MCP（MCP 工具）

步骤 4：外部资源（可跳过）​

按需启用 RAG 知识库 和 WebSearch 信源。

本步也可以完全跳过： 左侧 RAG、右侧 WebSearch 都不勾选（保持「已选 0/x」，如上图所示），直接点击右下角 创建 即可完成实例创建。说明文字同样提示：「RAG 与 WebSearch 可按需启用，后续也能继续调整。」

区域说明
左侧 RAG需要知识库检索时再勾选。勾选前请先完成 QYRAG 部署 → QYRAG 配置，并在 RAG 中至少有一个知识库；否则列表可能为空
右侧 WebSearch需要搜索时再勾选。勾选前请先在 Web Search 中添加并配置好信源；否则列表可能为空
创建无论是否勾选，都可以点击提交

相关手册：

  • RAG（知识库）（含全局检索联调）
  • Web Search（信源管理）（含全局检索联调）

创建后若未在本步勾选，也可在各模块列表页对 运行中 实例单独 部署。

点击 创建 后，实例会依次经历 创建中 → 初始化服务 → 运行中。首次启动可能需要一段时间，可刷新页面查看进度。

打开实例 WebUI​

实例 运行中 后，在实例卡片上点击 WebUI（或通过卡片菜单进入），即可打开对话界面。

下图以提问「贸易战依据什么法案发起的？」为例，说明对话界面的各部分含义。

界面分区​

区域位置你能做什么
会话列表左侧窄栏点击 发起新对话 开始新任务；查看历史会话
对话主区中间查看你的提问、智能体回复，以及推理过程
能力面板右侧切换 工作区 / 技能 / MCP / 定时，管理文件和已挂载能力
输入区底部输入任务指令并发送；切换当前使用的模型

一次对话里会发生什么​

发送问题后，智能体会按步骤处理任务，界面会实时展示过程：

  1. 显示你的问题 — 右侧紫色气泡，例如「贸易战依据什么法案发起的？」
  2. 展开工作思路 — 中间区域出现「耗时 x 分 x 秒 · N 段工作思路」，点击可展开每一步推理
  3. 调用工具 — 每步下方会显示调用了哪些工具，绿色勾表示执行成功

常见工具名称及含义：

工具作用
nineclaw_search通过 WebSearch 在互联网搜索相关信息
nineclaw_extract从网页链接中提取正文内容
QYRAG_retrieve从已关联的 RAG 知识库中检索文档片段

上图中，智能体先联网搜索，再检索「贸易战」知识库，最后综合信息给出回答。如果你在创建实例时勾选了 RAG 和 WebSearch，对话中就会自动使用这些能力。

右侧「技能」面板​

切换到 技能 标签页，可以查看当前实例已挂载的 Skill 分类（如 autonomous-ai-agents、data-science 等），并通过开关启用或关闭特定技能。只有创建实例时勾选、或后续部署过的 Skill 才会出现在这里。

底部操作​

控件说明
输入框输入任务指令，按回车或点击发送；可用 ↑ / ↓ 翻看本会话最近发送过的内容
模型选择右下角下拉框切换当前模型；若已在模型栈中 保存至少一个启用预设，可展开 Mixture of Agents 选用 MoA（见 配置模型栈）。没有预设时列表中不会出现 MoA
+ 按钮添加附件；文件会直接进入当前会话选中的工作区（Agent 与工作区文件树都能看到），不再先丢进「聊天附件收件箱」
停止按钮任务执行中可点击中断当前回复

使用中文输入法时：组字过程中按回车只上屏文字，不会误发送；组字结束后再按回车才会发送。

发送一条简单消息（例如「你好」）能收到回复，说明实例运行正常；发送需要查资料的问题，能看到工具调用过程，说明 RAG、WebSearch 等能力已生效。

工作区文件与文件夹​

在右侧能力面板切换到 工作区，可浏览、上传、预览会话相关文件。

操作说明
上传 / 对话附件进入当前选中的工作区目录，供智能体读写
预览文本、PDF、图片、音视频、Word（.docx / .doc）等按类型预览
删除文件夹会删除该文件夹及其内部全部内容；确认框会明确提示「文件夹内的全部内容将一并删除」

删除前请确认没有仍需保留的文件。单个文件删除不影响其它目录。

配置模型栈（MoA）​

模型栈（界面全称 Mixture of Agents / MoA，侧栏副标题「多模型混合代理」）是某一个 Runtime 实例里的对话策略：用多个参考模型并行分析，再用一个聚合模型汇总并负责最终回复与工具调用。

请与 Models管理 区分开：

Models本文「模型栈」
配置位置左侧导航 Models 页面实例内 设置 → 配置 → 模型栈
作用登记供应商（Base URL、API Key）并 部署到实例把已部署到本实例的模型组合成 MoA 预设
是否必须有实例添加供应商不需要；部署需要必须先有 运行中 的实例

推荐顺序： 先在 Models 完成添加与部署 → 实例进入 运行中 → 再打开模型栈配置。若实例还没有可用模型，模型栈页会提示「MoA 暂不可用」。

如何打开​

  1. 打开 NineClaw WebUI，进入 NineClaw，点进一个 运行中 的实例（例如「研发助手」）。
  2. 在左侧会话栏底部点击 设置（齿轮图标）。若会话栏是收起的，先点展开，再点 设置。
  3. 弹出标题为 配置 的对话框；左侧菜单第二项为 模型栈（多模型混合代理）。

图中左侧依次为：模型设置（主模型 / 辅助模型）、模型栈（MoA）、以及 SOUL.md / MEMORY.md 等人格与工作区文件。「模型设置」决定默认单模型；「模型栈」配置多模型混合，二者不同，可同时存在。

  1. 点击 模型栈，等待「正在加载模型栈配置」结束。打开本页时系统会尽量自动检测并适配本实例已部署的模型。

页面上有什么​

区域说明
刷新 / 保存重新加载适配结果；改完预设后必须点 保存 才会生效
高级：OpenRouter / Codex可选。仅当你要改用 Hermes 内置 openrouter / openai-codex 组合时才需要；日常用本实例已部署的 modelstack 等 Provider 时可忽略
默认预设对话里选用 MoA 时的默认方案，例如 Mixture of Agents / default；无预设时显示「选择默认 MoA 预设」
预设列表可 新增预设、开关 启用、删除预设。若列表为空（提示「暂无 MoA 预设」），对话模型下拉里不会出现 Mixture of Agents

每个预设至少包含：

字段含义
参考模型顾问角色，可多个，并行分析问题（图中示例：modelstack / Kimi-k2.5、modelstack / GLM-5）
聚合模型主回复角色，汇总参考意见，并负责工具调用（图中示例：modelstack / MiniMax-M2.7）
参考模型最大 tokens可选，限制顾问输出长度，加快响应（示例 600）
聚合模型 max_tokens可选，限制最终回复长度（示例 4096）

保存要求：每个启用的预设须有 至少一个参考模型 和 一个聚合模型，且这些模型须已在本实例可用（来自 Models 部署结果）。保存成功后，对话页模型列表才会出现对应 MoA 选项。

无预设不可选 MoA： 预设列表为空，或全部预设关闭了 启用，对话输入框旁的模型下拉里都不会出现「Mixture of Agents」。请先 新增预设 并 保存。

在对话中选用 MoA​

配置并保存后，回到对话页：

  1. 点击输入框右侧的模型名称（当前可能显示 modelstack / … 等）。
  2. 在弹出列表中展开 Mixture of Agents，选择对应预设（如 MoA: default）。
  3. 之后发送的消息即按该 MoA 预设运行。

也可在 配置 → 模型设置 里把主模型设为单个 modelstack / … 模型（单模型模式），与选用 MoA 预设不冲突：前者是默认单模型，后者是多模型混合；对话时以右下角当前选中的项为准。

若你刚删光了所有预设并保存，而对话仍停在某个 MoA 选项上，系统会自动切回其它可用模型。

模型栈常见问题​

现象处理
打开模型栈提示暂不可用先到 Models 部署至少一个供应商到本实例，再点「重试自动适配」或刷新
下拉里没有 Mixture of Agents正常情况： 尚未新增/保存启用预设，或预设全部关闭了「启用」。到 设置 → 模型栈 新增并保存后再刷新对话页
选了 MoA 无回复或报错检查参考/聚合模型是否仍在线、API Key 是否有效；先在 Models 测连通，再回到模型栈重新适配
和「模型设置」搞混「模型设置」管主模型/辅助任务模型；「模型栈」管 MoA 多模型编排

管理实例​

实例 运行中 / 已停止 时，可用卡片悬停上的 启动 / 停止，或右上角 ⋮ 菜单：

操作什么时候使用
启动实例已停止，需要恢复使用（进入详情前必须先启动）
停止临时不使用该实例，释放资源
重启配置更新后需要重新加载，或实例异常时尝试恢复
编辑在 ⋮ 菜单中（链接项上方），修改实例相关信息
删除不再需要该实例

删除实例会移除该运行环境，请确认没有业务正在使用后再操作。

创建后补充部署资源​

如果在创建向导中跳过了 Skill、MCP、RAG 或 WebSearch，可以稍后在对应资源页面单独部署：

  1. 确认目标实例处于 运行中。
  2. 进入对应资源页面完成配置。
  3. 点击 部署，选择目标实例。
  4. 等待部署完成后，打开实例 WebUI 验证效果。
资源说明
Models管理新增或更换模型
Skill（技能库）给实例增加可复用技能
RAG（知识库）让实例可以使用知识库检索
MCP（MCP 工具）给实例接入外部工具
Web Search（信源管理）让实例可以使用搜索信源

若需接入外部知识库（QYRAG / RAGFlow），请先完成 QYRAG 部署，再在 QYRAG 配置 中完成对接（含 设置 → 外部知识库 的测试连接与保存），最后在 RAG 创建知识库并 部署 到本实例。

部署前可用两个「全局检索」页做联调（不会写进实例，仅平台侧验证）：

  • RAG 列表 → 检索（多知识库问答）
  • Web Search 列表 → 检索（多信源聚合）

详见 概览 — 两个全局检索。

常见排查​

现象优先检查
创建失败，提示 Docker 镜像不存在在部署机执行 docker images，确认是否存在 NINECLAW_IMAGE 对应标签（如 nineclaw:v2026.7.7.2）。没有则用交付包 docker_images/ 执行 docker load，或把 Manager 的 NINECLAW_IMAGE 改成已导入的标签后重启 Manager
创建后一直未运行服务器资源是否足够；Runtime 镜像是否已导入且标签正确
模型列表为空是否已在 Models 页面 添加 供应商；若已创建实例，是否已完成 部署
部署时找不到实例实例是否处于 运行中 状态
WebUI 打不开Traefik、Runtime 容器是否正常运行
对话无回复或报错主模型是否可用，API Key 和网络是否正常
模型栈 / MoA 不可用是否已部署模型到实例；是否在 设置 → 模型栈 保存了至少一个启用预设（无预设时对话里本身不会出现 MoA，见 配置模型栈）
部署后能力没有生效是否部署到正确实例，必要时重启实例
点进卡片提示请先启动实例是否为 已停止；先启动再进详情
删除工作区文件夹失败 / 删不干净确认弹框后应整夹删除；刷新后重试；旧版 WebUI 请升级
对话附件找不到是否在当前会话工作区中查看；附件会直接进选中工作区
