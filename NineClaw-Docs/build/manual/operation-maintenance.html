运维管理

本文面向已完成 系统部署 的用户，说明日常运维操作：启停服务、升级组件、卸载系统。

入口： 进入部署目录，执行 ./deploy.sh，在主菜单选择对应功能。

cd /opt/NineClaw-Deploy    # 换成你实际的部署目录
./deploy.sh

界面操作用法：

按键作用
↑ / ↓上下移动光标，选择菜单项
空格切换勾选状态（更新服务选择时使用）
Enter确认当前选项，进入下一步
ESC返回上一级或退出

主菜单共有四项：

选项什么时候用
1 NineClaw 安装第一次安装，或整包重装（见 系统部署）
2 NineClaw 管理启停、重启平台服务（docker compose）
3 NineClaw 更新收到新版本镜像，升级指定服务组件
4 NineClaw 卸载不再使用，需要卸载 NineClaw

NineClaw 管理​

适用场景： 平台已安装，需要启动/停止/重启 Traefik、Manager、WebUI 等 固定容器（不是 WebUI 里的 Runtime 实例）。

管理功能不会改 .env，不会删业务数据，只对 Docker 容器做启停。

关于菜单名称

界面选项如「随系统开机启动」是 deploy.sh 菜单原文，实际执行 docker compose up -d 等命令。不会配置 Linux 操作系统开机自启。完成提示里的「随系统自动启动」指容器在 Docker 中后台运行。

管理流程：

图一  主菜单 → 选「2 NineClaw 管理」
图二  管理子菜单 → 选一项操作 → Enter 执行
图三  「完成」对话框 → 确认提示 → Enter 返回

图一：打开主菜单，选择「管理」​

在部署目录执行 ./deploy.sh，进入 NineClaw 部署工具 主菜单。

图中可见：

  • 标题 「NineClaw 部署工具」
  • 四项菜单，当前高亮 「2 NineClaw 管理」（红底白字）
  • 底部 <进入 [Enter]>、<退出 [ESC]>
选项用途
1 NineClaw 安装首次安装或整包重装（见 系统部署）
2 NineClaw 管理启停、重启平台服务 ← 选这个
3 NineClaw 更新升级指定服务组件
4 NineClaw 卸载停止并移除容器

操作： 用 ↑ / ↓ 移到 「2 NineClaw 管理」，确认已高亮后按 Enter。误选时按 ESC 返回。

图二：选择管理操作​

进入后，界面标题变为 NineClaw 管理，顶部显示当前状态，下方列出四项操作。

图中可见：

  • 状态行：「当前状态：运行中（5 个服务）」（你的实际数字可能不同）
  • 当前高亮 「1 随系统开机启动 (docker compose up -d)」
  • 底部 <执行 [Enter]> 执行选中项，<返回 [ESC]> 退回主菜单
选项对应命令做什么什么时候选它
1 随系统开机启动docker compose up -d启动全部服务，后台持续运行服务未启动、服务器重启后需恢复
2 关闭随系统启动docker compose down停止并移除全部容器及网络彻底停服、卸载前准备
3 启动或恢复服务docker compose restart重启全部服务改了 .env、服务异常、更新后需刷新
4 暂停至下次重启docker compose stop停止容器但不删除临时维护、关机前暂停（数据保留）

操作： 用 ↑ / ↓ 选中目标项，按 Enter 执行；按 ESC 返回主菜单。

1 随系统开机启动​

执行 docker compose up -d，后台启动全部平台服务。终端关闭后服务仍继续。

若需 服务器重启后自动拉起，须按交付说明单独配置 systemd 等机制，本菜单项不负责此项。

2 关闭随系统启动​

执行 docker compose down，停止并移除全部容器和网络。期间 WebUI 不可访问属正常。

默认不删数据卷；要连同数据清除，请走 NineClaw 卸载。

3 启动或恢复服务​

执行 docker compose restart，依次重启全部服务，通常 1～3 分钟。改 .env 后选此项使配置生效。

4 暂停至下次重启​

执行 docker compose stop，停止容器但不删除容器、网络和数据卷。恢复时选 「1」 或 「3」。

与 「2」 的区别：4 保留容器，2 会移除容器。

图三：确认操作完成​

执行所选操作后，弹出 「完成」 对话框。

图中可见（以「随系统开机启动」为例）：

  • 标题 「完成」
  • 提示：✓ NineClaw 已启动，并将随系统自动启动。
  • 底部红色按钮 <确认 [Enter]>

操作： 确认文字与预期一致后，按 Enter 关闭对话框，返回主菜单。

怎么判断管理操作成功​

所选操作成功的表现
1 随系统开机启动弹出完成提示；浏览器能打开 http://服务器地址:8510
2 关闭随系统启动弹出完成提示；WebUI 无法访问；docker compose ps 无运行中容器
3 启动或恢复服务弹出完成提示；各服务恢复 Up；WebUI 可正常访问
4 暂停至下次重启弹出完成提示；WebUI 暂时不可访问；容器状态为 Exited（未删除）

常见情况怎么处理​

现象建议操作
WebUI 打不开先选 「1 随系统开机启动」；若仍异常，再选 「3 启动或恢复服务」
刚改了 .env选 「3 启动或恢复服务」，让新配置生效
服务器要关机维护选 「4 暂停至下次重启」；维护完再选 「1 随系统开机启动」
需要彻底停服选 「2 关闭随系统启动」

NineClaw 更新​

适用场景： 交付包提供了新版本镜像，需要升级部分或全部服务。

更新会替换所选服务的 Docker 镜像并重启对应容器。不会自动覆盖 .env 和业务数据；更新前建议备份 .env。

更新流程：

图四  主菜单 → 选「3 NineClaw 更新」
图五  勾选服务 → Enter 开始（终端：导入镜像 → 重启容器）
图六  「更新完成」→ 核对服务名 → Enter 返回

更新过程与结果​

更新分四步，中间不要关终端：

步骤界面表现你该做什么
1. 选服务图五多选列表空格勾选，Enter 开始
2. 导镜像终端显示「正在导入…」等待，不要 Ctrl+C
3. 重启终端显示 Recreate / Started继续等待；WebUI 可能短暂不可用
4. 看结果图六「更新完成」对话框核对服务名，Enter 返回

每个勾选的服务，结果通常是下面三种之一：

结果怎么判断下一步
已更新出现在图六列表中做 验证更新结果
已跳过未出现在图六，终端提示跳过检查 docker_images/ 是否有新镜像
失败终端报错，流程中断保留报错，联系交付或运维

图四：打开主菜单，选择「更新」​

图中可见：

  • 主菜单四项，当前高亮 「3 NineClaw 更新」
  • 底部 <进入 [Enter]>、<退出 [ESC]>

操作： 用 ↑ / ↓ 移到 「3 NineClaw 更新」，按 Enter 进入。镜像文件未同步到位时，按 ESC 退出，补齐 docker_images/ 后再来。

更新前准备

建议先备份 .env：cp .env .env.bak.$(date +%Y%m%d)。若交付包中有新版 docker_images/，请先将镜像文件同步到部署目录后再执行更新。

图五：选择要更新的服务​

图中可见：

  • 标题 「选择要更新的服务」
  • 提示 「空格切换，回车确认：」
  • 七个服务（顺序与界面一致），[ ] 为未选，[x] 为已选
  • 底部 <确认 [Enter]> 开始更新，<取消 [ESC]> 返回
服务名做什么的单独更新时检查什么
docs在线文档 http://服务器地址:8510/docs文档页面能打开、内容正确
opensandbox-server实例内沙箱执行需要跑代码/命令的任务正常
postgres数据库（Manager、WebSearch 数据）先备份；登录后数据未丢失
nineclaw-manager后端管理 API实例列表、模型部署等功能正常
nineclaw-websearch信源搜索与网页抽取搜索、抽取能返回结果
nineclaw-webuiWeb 管理界面各页面能打开、操作无报错
traefik统一入口（8510 / 8511）WebUI、文档、API 均可访问

操作： ↑ / ↓ 移动光标，空格 勾选/取消，选好后按 Enter 开始更新。

选择建议：

你的情况建议选择
交付说明要求全量升级七个服务全部勾选
仅某个组件有问题只勾选对应服务（如仅 WebUI 异常则只选 nineclaw-webui）
只升级文档只勾选 docs
不确定该更新哪个联系交付人员确认，避免误更新 postgres 等关键组件
更新 postgres 前请备份

postgres 承载 Manager 与 WebSearch 的业务数据库，单独更新前务必确认已备份数据，并在测试环境验证过升级流程。

图六：确认更新完成​

图中可见：

  • 标题 「更新完成」
  • 提示 ✓ 以下服务已更新：，下方列出本次成功的服务名（图中示例为 traefik）
  • 底部 <确认 [Enter]>

若同时更新了多个服务，列表会逐行列出所有已更新的名称。

对照勾选结果：

情况怎么处理
勾选的服务都在列表里更新成功，进入 验证更新结果
部分勾选的服务不在列表里多半是交付包无新镜像（已跳过），看终端有无报错
终端中途报错更新失败，保留终端输出，联系交付或运维

确认后按 Enter 返回主菜单。

验证更新结果​

  1. 执行 docker compose ps，相关容器应为 Up（刚重启时可能短暂 Restarting）。
  2. 打开 http://服务器地址:8510，确认能登录。
  3. 按更新的组件抽测（见图五表格「单独更新时检查什么」列）。

怎么判断更新成功​

  • 图六对话框列出了你预期应升级的全部服务（若某服务被跳过，需确认是否本就没有新镜像）
  • docker compose ps 显示相关容器均为 Up
  • WebUI 能正常打开、登录
  • 与所更新组件相关的功能可正常使用

更新时注意​

注意点说明
不要中断终端镜像导入和服务重启过程中断可能导致状态不一致
保留原 .env新版配置项可对照 env.example 手动补充，不要整文件覆盖
选择性更新不必每次全选七个服务，按交付说明或实际需求勾选即可
更新失败不要反复重试；保留终端报错信息，联系交付或运维人员

NineClaw 卸载​

适用场景： 服务器不再运行 NineClaw，或需要彻底清空环境后重装。

卸载会停止并移除 NineClaw 相关容器。是否同时删除 .env、数据卷和镜像，由图九决定。

卸载流程：

图七   主菜单 → 选「4 NineClaw 卸载」
图八   确认不可逆 → Enter 继续 / ESC 取消
图九   删数据 Enter / 留数据 ESC
图十   终端执行卸载（勿关窗口）
图十一 「卸载完成」→ Enter 返回

图七：打开主菜单，选择「卸载」​

图中可见：

  • 主菜单四项，当前高亮 「4 NineClaw 卸载」
  • 底部 <进入 [Enter]>、<退出 [ESC]>

操作： 用 ↑ / ↓ 移到 「4 NineClaw 卸载」，按 Enter。尚未备份时按 ESC 返回，先完成备份。

卸载前请备份

建议先备份 .env 和业务数据：cp .env ~/nineclaw-env-backup-$(date +%Y%m%d).bak。数据库、知识库等是否需单独导出，请按运维规范或联系交付人员确认。

图八：确认卸载（不可逆）​

图中可见：

  • 标题 「NineClaw 卸载」
  • 提示：「即将卸载 NineClaw，此操作不可逆。」
  • 当前高亮 <继续 [Enter]>，右侧为 <取消 [ESC]>
按键作用
Enter继续卸载，进入下一步
ESC取消，返回主菜单

操作： 已备份且确认要卸载 → 按 Enter；误进或未备份 → 按 ESC。

图九：选择是否删除用户数据​

图中可见：

  • 标题 「用户数据」
  • 提问：「是否同时删除用户数据？」
  • 【删除】 将移除 .env、network、volume 及所有相关镜像
  • 【保留】 仅停止并移除容器，数据保留
  • 当前高亮 <删除数据 [Enter]>，右侧为 <保留数据 [ESC]>
按键做什么
Enter删除数据：容器、配置、数据卷、镜像一并清除
ESC保留数据：只移除容器，.env 和数据卷留在磁盘

操作： 需要彻底清空环境 → Enter；以后可能重装、想保留数据 → ESC。选删除前请确认备份可用。

项目删除数据保留数据
容器移除移除
.env / 数据卷 / 镜像删除保留
能否恢复仅能从备份恢复重装后可能沿用原数据

图十：执行卸载，等待完成​

图中可见（以「删除数据」为例）：

  • 标题行 卸载 NineClaw (删除数据)
  • 阶段一 — 停止并移除容器及数据卷 —
  • 阶段二 — 删除镜像 —，逐条显示如 删除: pgvector/pgvector:pg17、删除: traefik:v3.6 及 Untagged / Deleted: sha256:... 等输出

操作： 等待终端输出结束，不要关闭窗口。全部完成后会自动进入图十一。

图十一：确认卸载完成​

图中可见：

  • 标题 「卸载完成」
  • 删除数据时提示：✓ NineClaw 已卸载，数据已清除。
  • 底部 <确认 [Enter]>

若图九选了 保留数据，提示为 ✓ NineClaw 已卸载。（数据仍在磁盘上）。

操作： 确认文字符合预期后，按 Enter 返回主菜单。

验证卸载结果​

卸载完成后，在部署目录执行：

docker compose ps

成功的表现：

  • 无 NineClaw 相关容器处于 Up 状态（列表为空或提示无服务）
  • 若选择了 删除数据，浏览器访问原 WebUI 地址已无法打开
  • 若选择了 保留数据，可用 docker volume ls 查看数据卷是否仍在

卸载后怎么办​

情况怎么做
需要重新安装回到 系统部署，执行 「1 NineClaw 安装」；若保留了数据卷，数据是否自动衔接取决于版本与交付说明
仅清理部署目录确认无需要保留的数据后，可删除整个部署目录（不可恢复）
卸载不彻底联系运维检查是否有残留容器、网络或数据卷
误删数据需恢复只能从卸载前的备份恢复；无备份则无法找回

常见问题排查​

WebUI 打不开（平台服务问题）​

按顺序检查：

顺序检查什么怎么做
1平台服务是否在跑./deploy.sh → 「2 NineClaw 管理」 → 「1 随系统开机启动」；或 docker compose ps 看是否为 Up
2地址是否正确是否为 http://服务器地址:8510，且与 .env 中 PUBLIC_IP_OR_DOMAIN 一致
3防火墙 / 端口是否放通 8510、8511
4是否刚改过 .env「3 启动或恢复服务」 使配置生效
5看日志docker compose logs -f，把报错交给运维

能打开 WebUI 但功能异常（实例或配置问题）​

现象查阅
模型无回复Models — 确认已 部署 到 运行中 实例
知识库不可用先确认 http://服务器:8513 可打开（见 QYRAG 部署）；再查 QYRAG 配置、RAG。若 8513 与 NineClaw 库数量不一致，多为 API Key 账号与网页登录账号不同
知识库卡片一直失败 / 音视频无切片卡片五种状态与音视频说明见 RAG — 卡片状态、音频；检查 RAGFlow 解析是否成功
RAG 已对接但仍无法在对话中检索是否已把知识库 部署 到该 运行中 实例；知识库是否多为 已就绪；检查实例 .env 中 QYRAG_DATASETS（见 RAG — 部署）
实例未运行NineClaw
搜索无结果Web Search
实例操作超时 / 部署、打开实例仪表盘很慢本机是否临时开了系统 HTTP 代理（如 Clash 系统代理）；平台访问实例 不走环境代理。可关闭系统代理后重试，或检查 Manager / 实例网络
复制 ID 后粘贴为空是否用 http:// 局域网访问；请升级 WebUI（已改用不依赖受限剪贴板 API 的复制方式）

自查顺序：WebUI 能打开 → 实例为运行中 → 模型已部署 → （若用知识库）QYRAG 已对接且 RAG 已部署到该运行中实例。
