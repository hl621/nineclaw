概览

用户手册面向 NineClaw 的日常使用者，说明：怎么装、怎么运维、怎么在 WebUI 里配置各模块。

如果你是第一次使用，建议按下面「推荐阅读顺序」依次操作；若已安装完成，可从左侧导航直接进入对应模块。

推荐阅读顺序​

顺序做什么去哪里
1核对服务器与网络部署要求
2安装并启动 NineClaw系统部署
3日常启停、更新、卸载运维管理
4（若用知识库）先部署再对接 QYRAGQYRAG 部署 → QYRAG 配置
5添加模型 → 创建实例 → 部署模型Models管理、NineClaw
6按需配置 Skill / RAG / MCP / Web Search见下方模块导航

说明： 若只想先跑通对话，可把步骤 4（QYRAG）放到最后；与下方「快速上手路径」一致。左侧导航顺序已与本表对齐（先部署 QYRAG，再配置；系统配置里先 Models，再 NineClaw）。

WebUI 入口​

NineClaw WebUI 地址：http://<服务器地址>:8510（将 <服务器地址> 换成部署时填写的 IP 或域名，即 .env 中的 PUBLIC_IP_OR_DOMAIN）。

打不开时：先查 系统部署 — 第四步，再查 运维管理 — 常见问题。

两个层次，不要混淆​

手册里会出现两种「运行」说法，含义不同：

层次在哪里看指什么相关文档
平台服务服务器上执行 docker compose psTraefik、Manager、WebUI 等固定容器是否在跑运维管理
Runtime 实例WebUI → NineClaw 页面卡片状态单个对话实例是否 运行中NineClaw
  • WebUI 打不开 → 先处理平台服务（deploy.sh → NineClaw 管理）。
  • 能打开 WebUI 但无法对话 → 先确认实例为 运行中，且模型已 部署 到该实例。

先理解「配置」和「部署」​

NineClaw 里几乎所有能力都分两步：

步骤在哪里做做完之后
配置（添加 / 创建 / 注册）Models、Skill、RAG、MCP、Web Search 等页面资源进入平台资源库，实例还不能用
部署各页面点击 部署，选择 运行中 的实例实例 Runtime 才真正加载该能力

记一句：先配进平台，再部署到实例。 部署时实例必须是 运行中。

首次初始化步骤与 系统部署 — 第五步 一致。

系统配置页面​

左侧 系统配置 分类下的页面（建议按表中顺序理解「先模型、再实例、再业务资产」）：

配置项作用
Models管理接入大模型，并部署到实例
ASR 语音转写Models 里试听供应商 ASR（上传音频；与知识库预览无关）
NineClaw管理 Runtime 实例（创建、启停、打开对话 WebUI）
Skill（技能库）管理技能，并部署到实例
RAG（知识库）管理文档知识库，并部署到实例
MCP（MCP 工具）接入外部工具，并部署到实例
Web Search（信源管理）配置搜索信源，并部署到实例

编排 / 工作流： 侧栏若出现「编排」且标注研发中，表示能力仍在开发，当前 dev 交付不以编排画布为正式功能；请勿按未开放页面操作。正式说明将在功能上线后补充。

知识库还依赖 QYRAG（RAGFlow） 后台服务。侧边栏 QYRAG 部署 说明安装，QYRAG 配置 说明与 NineClaw 对接。

两个「全局检索」，不要混用​

入口页面标题查什么文档
RAG 列表 → 检索NineClaw RAG多个知识库文档RAG — 全局检索
Web Search 列表 → 检索NineClaw Search多个搜索信源Web Search — 全局检索

MCP 没有全局检索页；部署前请在 MCP 详情页做单工具试调。

快速上手路径​

只想尽快跑通对话，按下面做：

  1. 部署要求 → 系统部署，确认 WebUI 能打开。
  2. Models 添加至少一个模型供应商。
  3. NineClaw 创建实例，等到 运行中。
  4. 回到 Models 部署模型到该实例。
  5. 打开实例 WebUI，发一条消息验证。
  6. （可选）QYRAG 部署 → QYRAG 配置 + RAG；或按需配置 Skill / MCP / Web Search 并 部署 到实例。

已知要配置什么时，直接从左侧导航进入对应页面即可。
