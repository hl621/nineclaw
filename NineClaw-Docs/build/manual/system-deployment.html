系统部署

这篇文档面向第一次部署 NineClaw 的用户。按步骤操作即可，无需理解每个容器的实现细节。

完成后你应该能够：

  1. 在 Linux 服务器上安装并启动 NineClaw
  2. 用浏览器打开 WebUI（默认端口 8510）
  3. 完成模型、实例等基础初始化
  4. 在实例 WebUI 中完成一次对话验证

部署前请先阅读 部署要求，确认 Docker、端口 8510 等条件已满足。

文档结构（按顺序阅读）​

步骤内容预计耗时
第一步确认交付包文件齐全1 分钟
第二步进入目录并赋予脚本执行权限1 分钟
第三步运行 deploy.sh，完成安装与启动5～30 分钟（视镜像大小）
第四步检查服务状态，打开 WebUI2 分钟
第五步配置模型、创建实例、对话验证10～30 分钟

日常运维（启停、更新、卸载）不在本文范围，请见 运维管理。

你需要准备什么​

需要准备说明
一台 Linux 服务器运行 NineClaw 全部容器
部署包通常由交付方提供，含脚本、配置和离线镜像
Docker + Docker Compose版本要求见 部署要求
whiptail部署工具交互界面依赖（Ubuntu/Debian：sudo apt install whiptail）

第一步：检查部署包​

解压交付包后，目录结构应类似：

NineClaw-Deploy/
├── deploy.sh              # 安装入口（后面主要运行它）
├── docker-compose.yml     # 服务编排（一般无需手改）
├── env.example            # 环境变量模板（安装时生成 .env）
└── docker_images/         # 离线镜像包（脚本自动导入）
    └── bundle-split/      # 可选：镜像切分包，脚本会自动合并

若缺少上述文件，请先联系交付方补齐部署包。

第二步：进入部署目录​

将部署包放到服务器，例如 /opt/NineClaw-Deploy，然后执行：

cd /opt/NineClaw-Deploy
chmod +x deploy.sh

第三步：运行安装脚本​

在部署目录执行：

./deploy.sh

会进入 NineClaw 部署工具（蓝色背景的交互界面）。

按键说明：

按键作用
↑ / ↓移动光标
Enter确认
ESC取消 / 返回 / 退出

安装流程一览（请按顺序完成 3.1 → 3.6）：

3.1 主菜单 → 选「NineClaw 安装」
3.2 网络配置 → 填写对外 IP
3.3 确认地址 → 确认写入 .env
3.4 自动执行 → 创建网络 + 导入镜像（终端输出，等待即可）
3.5 安装完成 → 选「立即启动」或「稍后启动」
3.6 启动完成 → 看到「NineClaw 已启动」（仅在选择「立即启动」时出现）

3.1 打开主菜单，选择「安装」​

选项用途
1 NineClaw 安装首次安装或整包重装 ← 选这个
2 NineClaw 管理启停、重启平台服务（装好后日常用，详见 运维管理）
3 NineClaw 更新导入新镜像并升级
4 NineClaw 卸载停止并移除容器

操作： 选中 「1 NineClaw 安装」（红色高亮）→ 按 Enter。

3.2 填写部署机对外 IP​

提示：「请输入部署机对外访问 IP 地址。」

填写其他电脑访问本服务器时使用的 IP 或域名，然后按 Enter。

场景建议填写
同事从办公网访问服务器内网 IP，如 172.18.33.27
仅本机访问可填 127.0.0.1，但更推荐填真实网卡 IP
有域名填已解析到本机的域名
这个地址很重要

安装脚本会把该地址写入 .env 的 PUBLIC_IP_OR_DOMAIN，后续 WebUI、文档等访问链接都依赖它。填错会导致浏览器打不开页面。

3.3 确认写入 .env 的地址​

界面会显示即将写入的内容，例如：

PUBLIC_IP_OR_DOMAIN=172.18.33.27
按钮操作
确认 [Enter]地址无误，继续安装
重新输入 [ESC]返回上一步修改

确认后，脚本从 env.example 生成或更新 .env。

3.4 创建网络并导入镜像​

确认 IP 后，脚本在终端文字界面自动执行，无需再点菜单。界面类似：

（1）创建 Docker 网络​

创建 Docker 网络: qiyuan_net
网络 qiyuan_net 已存在，跳过。
  • 首次安装：自动创建 qiyuan_net
  • 重复安装：提示「已存在，跳过」—— 正常现象

（2）导入离线镜像​

导入镜像
  正在导入 nineclaw-images-bundle-20260702.tar.gz ...
  预计耗时 < 1 分钟
  ...
  全部镜像导入完成
  • 镜像包文件名中的日期（如 20260702）随交付包版本变化，以你目录里实际文件为准
  • 若存在 docker_images/bundle-split/ 切分包，脚本会先合并再导入

常见导入镜像包括：

镜像用途
traefik:v3.6统一入口与路由
pgvector/pgvector:pg17数据库
nineclaw-manager:latest编排与管理 API
nineclaw-webui:latestWeb 管理界面
nineclaw-websearch:latest信源搜索
nineclaw-docs:latest在线文档
opensandbox-server（镜像名以包内为准）沙箱执行服务
nineclaw:v2026.x.x实例运行时（版本以包内为准）

你要做的： 等待完成，不要 Ctrl+C 中断。大镜像包可能需要数分钟。

3.5 安装完成，选择是否立即启动​

提示：「所有准备工作已就绪，是否立即启动 NineClaw?」

按钮含义
立即启动 [Enter]执行 docker compose up -d（首次部署推荐）
稍后启动 [ESC]只完成安装，不启动服务
若选择了「稍后启动」

不会看到 3.6。请之后执行 ./deploy.sh → 「2 NineClaw 管理」 → 「1 随系统开机启动」，再进入 第四步。菜单说明见 运维管理。

3.6 启动完成​

（仅在选择 「立即启动」 后出现。）

显示 「✓ NineClaw 已启动。」 → 按 Enter 返回主菜单。

此时安装与启动均已完成，继续 第四步。

第四步：确认系统已启动​

在部署目录执行：

docker compose ps

主要服务（traefik、postgres、nineclaw-manager、nineclaw-webui 等）状态应为 Up（或显示 running，均表示正常）。

访问地址​

将下表中的 服务器地址 替换为 3.2 / 3.3 填写的 IP 或域名（即 .env 中的 PUBLIC_IP_OR_DOMAIN）：

用途地址
NineClaw WebUIhttp://服务器地址:8510
在线文档http://服务器地址:8510/docs
Traefik 管理页http://服务器地址:8511

示例： 安装时填 172.18.33.27 → WebUI 为 http://172.18.33.27:8510

打不开 WebUI 时​

检查项怎么做
地址是否正确浏览器地址栏 IP 是否与 .env 中 PUBLIC_IP_OR_DOMAIN 一致
服务是否在跑docker compose ps 中相关容器为 Up / running
防火墙是否放通 8510、8511（见 部署要求）
是否选了「稍后启动」执行 ./deploy.sh → 「2 NineClaw 管理」 → 「1 随系统开机启动」

排查日志：docker compose logs -f（Ctrl+C 退出）。

第五步：完成系统初始化​

浏览器打开 http://服务器地址:8510 后，按下面顺序操作。

说明： 以下步骤在 WebUI 中完成，操作的是 Runtime 实例 与模型等资源，与 deploy.sh 里的平台服务启停不是同一层。两层区别见 概览 — 两个层次。

① 添加模型供应商 → ② 创建 NineClaw 实例 → ③ 部署模型到实例 → ④ 实例内对话验证
（可选）QYRAG / Skill / MCP / Web Search

1. 添加模型供应商​

路径：Models → + 添加

至少配置一个可用模型（名称、Base URL、API Key，点击 获取 选择模型），否则实例无法回答问题。

详见 Models管理。

2. 配置 QYRAG 连接（可选）​

仅在使用知识库时需要。 需先确保 QYRAG / RAGFlow 在 8513 端口可访问。

QYRAG 不在 NineClaw 安装包内，须单独部署。若 http://服务器地址:8513 无法打开，请先完成 QYRAG 部署，再按 QYRAG 配置 对接。

NineClaw 侧：设置 → 外部知识库 → 填写地址与 API Key → 测试连接 → 保存。

暂不用知识库可跳过。

3. 创建 NineClaw 实例​

路径：NineClaw → + 创建

向导步骤说明
1 容器配置名称、内存、CPU（必填）
2 模型配置有供应商可选主模型；列表为空可先跳过，创建后再部署
3 业务资产Skill / MCP 可跳过
4 外部资源RAG / WebSearch 可跳过

点击 创建，等待状态变为 运行中（可能需要几分钟）。

详见 NineClaw。

4. 部署模型到实例​

路径：Models → 部署

  1. 选择模型供应商
  2. 选择刚创建且 运行中 的实例
  3. 选择主模型
  4. 点击 开始，等待完成
容易遗漏的一步

只「创建实例」不会自动把模型写进实例；必须完成本步部署，实例才能调用模型对话。

5. 按需配置其他能力（可选）​

能力何时需要手册
RAG文档问答RAG（知识库）
Skill复用固定技能Skill（技能库）
MCP接入外部工具MCP（MCP 工具）
Web Search内网或公网搜索信源Web Search（信源管理）

配置后需在各自页面 部署到目标实例 才能生效。

模块截图
Skill
MCP
Web Search

6. 打开实例验证​

NineClaw 页面 → 运行中实例 → 点击 WebUI → 输入：

你好，请简单介绍一下你能做什么。

模型已部署成功时，应能收到正常回复。

初始化完成检查清单​

  • http://服务器地址:8510 可打开 WebUI
  • http://服务器地址:8510/docs 可打开文档
  • Models 中至少有一个可用模型供应商
  • 至少一个 NineClaw 实例为 运行中
  • 模型已 部署 到目标实例（非仅创建）
  • 实例 WebUI 内可正常对话
  • （可选）QYRAG 测试连接通过
  • （可选）Skill / MCP / Web Search 已部署到实例

常见问题​

现象可能原因处理
文档配图不显示static/img/ 缺少 PNG在 NineClaw-Docs 目录执行 node scripts/capture-deploy-wizard-screenshots.mjs 生成截图
WebUI 502 / 打不开IP 填错或服务未启动核对 PUBLIC_IP_OR_DOMAIN 与 docker compose ps
实例创建失败Docker 未就绪、资源不足，或 Runtime 镜像缺失查看 Manager / WebUI 报错；若提示「Docker 镜像不存在」，在部署机 docker images 核对 NINECLAW_IMAGE，必要时 docker load 交付包镜像；详见 NineClaw — 常见排查
实例创建失败（开发环境）远程 Docker / WSL 未就绪查看 Manager 日志；Windows 开发环境需 WSL + 远程 Docker
实例无法对话未部署模型到实例完成 第五步第 4 步
知识库不可用QYRAG 未部署、未对接，或未部署到实例先 QYRAG 部署，再 QYRAG 配置；然后在 RAG 部署 到运行中实例。排查表见 RAG / QYRAG 配置文档
