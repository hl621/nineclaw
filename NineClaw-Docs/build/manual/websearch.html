Web Search（信源管理）

Web Search 页面用于管理搜索信源，把外部搜索引擎、内部门户、业务系统查询入口等接入 NineClaw，让智能体在需要时获取知识库之外的信息。

在离线或内网环境下尤其有用：把企业内部可访问的信息源配置进来，智能体仍能「查资料」。

信源配置完成后，还需 部署 到 运行中 的 NineClaw 实例。也可在 NineClaw 创建实例 向导的步骤 4 中勾选 WebSearch。

难度提示： 信源详情页的「代码抽取」通常需要了解目标页面结构的技术人员参与；非技术人员可负责添加信源、做关键词测试，并确认抽取结果是否符合预期。

访问地址示例：http://xxx:8510/websearch

进入页面​

  1. 打开 NineClaw WebUI。
  2. 在左侧导航中点击 Web Search。
  3. 页面会展示已注册的信源。

页面上能看到什么​

区域说明
搜索框按名称、描述或信源 ID 查找信源
+ 添加新增信源
检索进入全局检索（聚合检索）页，测试多个信源的搜索效果
部署把信源配置部署到 NineClaw 实例
信源卡片展示信源名称、启用状态、权重和 ID

添加信源​

NineClaw 支持自主新增外部信源。弹窗只填名称等信息；搜索 URL、参数与抽取代码在详情页配置。

  1. 点击 + 添加。
  2. 填写 信源名称（必填）。
  3. 选填描述，设置权重。
  4. 点击 确认，进入配置，进入详情页；在 HTTP 测试 卡片内编辑 URL、参数、请求头与代理。

字段说明
信源名称页面展示名称（必填）
描述说明这个信源适合查什么
权重聚合检索时的排序参考，权重越高越优先

不用再填「信源 ID」。 与创建 Skill 类似：弹窗只关心名称等信息，内部标识由系统自动生成（如 src_…）。卡片上仍可复制该 ID，供部署与排障使用。

搜索 URL 在哪里改？ 进入信源详情后，在第一步 HTTP 测试 中修改请求方式、地址、参数、请求头与代理（须含 {query} 占位符）。

配置信源​

点击信源卡片进入详情页。顶栏与 RAG / Skill 详情一致：左侧为 返回、信源 Globe 图标、名称与描述；右侧为配置步骤条。

配置流程通常分三步。

HTTP 测试​

先配置如何请求目标站点，并用一个测试关键词确认能拿到返回内容。

区域说明
请求配置填写请求方式、地址、参数、请求头或请求体
测试关键词用来模拟真实搜索
发送请求拉取目标站点返回内容
响应面板查看原始内容或预览效果

代码抽取​

配置如何从返回内容中提取标题、链接和摘要。

这一步通常需要懂目标页面结构的人参与。如果你不是配置人员，只需要确认抽取结果是否符合预期。

用 AI 辅助编写 / 修复抽取代码​

在 代码抽取 面板中，可打开 AI 修复 / AI 编写 助手（与 Skill Studio 类似）：

你做什么系统做什么
描述想抽取的字段或贴出一段页面片段AI 生成或改写抽取代码
发现抽取结果不对让 AI 根据报错或样例结果继续修正
工具调用次数过多系统会限制无效重试，避免一直转圈

建议流程：先用「请求测试」拿到真实响应 → 再让 AI 写抽取 → 用「关键词测试」整链验证。

关键词测试​

用真实关键词完整测试一次：请求目标站点、抽取结果、展示搜索结果。

如果结果为空或明显不对，需要回到前两步检查请求配置和抽取逻辑。

全局检索（聚合检索）​

Web Search 的全局检索用于一次性查询多个已启用信源，并合并展示结果，适合部署前验证信源质量。它与信源详情页里的「关键词测试」不同：详情页只测单个信源，全局检索会聚合全部（或你在侧栏勾选的）信源。

访问地址示例：http://xxx:8510/websearch/search

进入全局检索​

  1. 打开 NineClaw WebUI，进入 Web Search 列表页。
  2. 确认至少有一个已启用且配置完成的信源。
  3. 点击工具栏 检索。
  4. 进入 NineClaw Search 检索页。

发起检索并查看结果​

  1. 输入关键词。
  2. 点击 检索。
  3. 查看多个信源合并后的结果。
  4. 按需打开右侧设置面板，临时调整参与检索的信源和权重。

全局检索适合在部署前验证信源质量。只有能稳定返回有效结果的信源，才建议部署给实例使用。

同类能力：RAG 列表页也有跨知识库的 全局检索，见 RAG（知识库）。MCP 模块没有全局检索入口。

部署到 NineClaw 实例​

部署前请确认目标实例处于 运行中。部署可能会让目标 Runtime 短暂重新加载，建议避开正在执行关键任务的时间窗口。

  1. 在 Web Search 列表页点击 部署。
  2. 选择要部署的信源。
  3. 选择一个或多个 运行中 的 NineClaw 实例。
  4. 点击 开始。
  5. 等待部署完成。

注意事项​

场景说明
信源未启用未启用的信源不会参与检索和部署
信源 ID创建后建议保持稳定，避免影响已有配置
权重只影响聚合排序，不代表结果一定正确
抽取逻辑目标页面结构变化后，抽取结果可能需要重新调整

常见排查​

现象优先检查
添加百度提示 Source already exists，但列表没有百度已知缺陷（已修）： 旧版创建只写了 config、没写抽取脚本，信源“占坑”却不显示。请升级 WebSearch 后刷新列表；或删除残留 ID 后重建
不知道信源 ID 怎么填已无需填写。 创建时系统自动分配（如 src_…）；卡片上可复制
搜索 URL 在哪改添加弹窗不填 URL；进入详情页第一步 HTTP 测试 卡片内编辑
添加弹窗里没有「信源模板」预期行为。 当前只填名称/描述/权重；URL 与抽取在详情页配置
HTTP 测试失败目标地址、参数、请求头、网络 / 代理、反爬是否拦截
抽取结果为空页面结构是否变化，抽取规则是否匹配；可试用 AI 辅助编写 后重测
AI 抽取一直转圈 / 工具调用过多升级 WebUI / Manager：已限制无效重试；缩短描述后重试
聚合 / 全局检索结果不好信源质量、权重、关键词是否合适
部署后实例无法搜索是否部署到正确实例，信源是否启用
