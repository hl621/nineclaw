QYRAG 部署与运维

本文说明如何使用 QYRAG 交付包里的 deploy.sh：安装、日常启停、升级组件、卸载 QYRAG（RAGFlow）。

完成后你应该能够：

  1. 在 Linux 服务器上安装并启动 QYRAG
  2. 用浏览器打开 RAGFlow 控制台（默认端口 8513）
  3. 继续 QYRAG 配置，完成与 NineClaw 的对接

与「QYRAG 配置」的区别：

文档做什么
QYRAG 部署与运维（本文）在 QYRAG 交付目录运行 deploy.sh：安装、启停、更新、卸载 RAG 后台服务
QYRAG 配置QYRAG 已在 8513 运行后，配置 RAGFlow 并与 NineClaw 对接
运维管理NineClaw 平台的 deploy.sh 启停（8510），与本文不是同一个脚本
与 NineClaw 的关系

QYRAG 使用独立的交付包和独立的 deploy.sh，不在 系统部署 的 NineClaw 安装包内。两台服务端口不同：NineClaw 8510，QYRAG 8513。若装在同一台服务器，可能共用 Docker 网络 qiyuan_net，提示「网络已存在，跳过」属正常现象。

部署前请先阅读 部署要求（端口 8513、Docker 版本、网络放通）。

所有操作都在 QYRAG 部署目录执行（例如 /opt/QYRAG-Deploy），运行 ./deploy.sh 后按菜单选择：

deploy.sh 菜单文档章节什么时候用
1 RAG 安装RAG 安装第一次部署，或整包重装
2 RAG 管理RAG 管理启停、重启（装好后日常用）
3 RAG 更新RAG 更新交付了新版本镜像
4 RAG 卸载RAG 卸载不再使用 QYRAG

按键（全篇通用）： ↑ / ↓ 移动光标 · Enter 确认 · ESC 返回或取消 · 更新时另用 空格 勾选服务

文档结构（按顺序阅读）​

文首 菜单对照表 已列出 deploy.sh 四项与文档章节的对应关系。首次部署只需读 RAG 安装 并完成 安装检查清单；管理、更新、卸载按需查阅。

RAG 安装​

适用场景： 第一次在服务器上部署 QYRAG（RAGFlow），或需要整包重装。

在 QYRAG 部署目录 执行 ./deploy.sh，选 「1 RAG 安装」。安装完成后继续 QYRAG 配置 与 NineClaw 对接。

安装流程：

安装前    检查交付包 → 进入部署目录
安装图一  主菜单 → 选「1 RAG 安装」
安装图二  终端自动执行 → 创建网络 + 导入镜像
安装图三  安装完成 → 立即启动 RAG / 稍后启动
确认      打开 http://服务器地址:8513 验证
与 NineClaw 安装的区别

NineClaw 系统部署 会弹出 「网络配置」 填写对外 IP（写入 PUBLIC_IP_OR_DOMAIN）。QYRAG 的 deploy.sh 没有这一步：选「1 RAG 安装」后直接创建网络并导入镜像。访问 RAGFlow 时，用本机实际可达的 IP/域名加端口 8513 即可。

安装前准备​

需要准备说明
QYRAG 交付包通常由交付方提供，含 deploy.sh、Compose 配置和离线镜像
Linux 服务器可与 NineClaw 同机，也可单独部署
Docker + Docker Compose版本要求见 部署要求
whiptail交互界面依赖（Ubuntu/Debian：sudo apt install whiptail）
网络放通 8513；若 NineClaw 在别的机器，须能访问本机 8513

检查交付包： 解压后目录结构应类似：

QYRAG-Deploy/              # 目录名以实际交付包为准
├── deploy.sh              # 安装入口（后面主要运行它）
├── docker-compose.yml     # 服务编排（一般无需手改）
├── env.example            # 环境变量模板（安装时生成 .env）
└── docker_images/         # 离线镜像 tar 包（脚本自动导入）

若缺少上述文件，请先联系交付方补齐。不要使用 NineClaw 安装包里的 deploy.sh 来装 QYRAG。

进入部署目录：

cd /opt/QYRAG-Deploy    # 换成你实际的 QYRAG 部署目录
chmod +x deploy.sh

运行 deploy.sh​

在 QYRAG 部署目录执行：

./deploy.sh

会进入 RAG 部署工具（蓝色背景的交互界面）。

（2）导入离线镜像​

确认安装成功​

在 QYRAG 部署目录 执行：

docker compose ps

QYRAG 相关容器（如 Elasticsearch、MinIO、PostgreSQL、RAGFlow 等）状态应为 Up（或 running）。

访问 RAGFlow​

将 服务器地址 替换为本机对外可达的 IP 或域名（即其他电脑访问该服务器时使用的地址；不是 NineClaw 安装时填写的对话框内容）：

用途地址
RAGFlow 控制台http://服务器地址:8513

示例： 服务器内网 IP 为 172.18.33.27 → RAGFlow 为 http://172.18.33.27:8513

能打开 RAGFlow 登录或注册页，表示 QYRAG 部署成功。

打不开 8513 时​

检查项怎么做
地址是否正确浏览器是否使用了服务器真实可达的 IP/域名，端口是否为 8513
服务是否在跑docker compose ps 是否均为 Up
防火墙是否放通 8513（见 部署要求）
是否选了「稍后启动」./deploy.sh → 「2 RAG 管理」 → 「1 随系统开机启动」

排查日志：docker compose logs -f（Ctrl+C 退出）。

安装检查清单​

  • http://服务器地址:8513 可打开 RAGFlow 页面
  • docker compose ps 显示 QYRAG 相关容器为 Up
  • NineClaw 所在机器能访问 8513（若与 QYRAG 不在同一台，需放通网络）

安装完成后下一步​

  1. QYRAG 配置 — RAGFlow 注册、模型、API Key、NineClaw 外部知识库
  2. RAG（知识库） — 在 WebUI 管理知识库（含音视频预览、卡片五种构建状态）
  3. RAG — 支持的文件格式 — 上传前确认扩展名是否支持
  4. 若尚未安装 NineClaw — 系统部署

RAG 管理​

适用场景： QYRAG 已安装，需要启动/停止/重启 RAG 后台容器（Elasticsearch、MinIO、PostgreSQL、RAGFlow 等）。

在 QYRAG 部署目录（不是 NineClaw 部署目录）执行 ./deploy.sh，选 「2 RAG 管理」。

管理功能不会改 .env，不会删知识库数据，只对 QYRAG 的 Docker 容器做启停。

关于菜单名称

选项如「随系统开机启动」是 deploy.sh 菜单原文，实际执行 docker compose up -d 等命令。不会配置 Linux 操作系统开机自启。完成提示里的「随系统自动启动」指容器在 Docker 中后台运行。

不要与 NineClaw 运维混淆

本文操作的是 QYRAG 交付目录里的 deploy.sh（8513）。NineClaw 平台（8510）见 运维管理。两个目录、两个脚本，互不影响。

管理流程：

管理图一  主菜单 → 选「2 RAG 管理」
管理图二  管理子菜单 → 选一项操作 → Enter 执行
         （执行中终端可能显示卷/容器创建进度）
管理图三  「完成」对话框 → 确认提示 → Enter 返回

选项对应命令做什么什么时候选它
1 随系统开机启动docker compose up -d启动全部 QYRAG 服务安装时选了「稍后启动」、服务器重启后需恢复、8513 打不开

四项操作说明​

选项要点
1 随系统开机启动后台拉起全部容器；终端可能显示创建数据卷、启动 qy-rag-* 容器（见下图）
2 关闭随系统启动停止并移除容器；期间 8513 不可访问属正常；默认不删数据卷
3 启动或恢复服务依次重启，通常 1～3 分钟；改 .env 后选此项
4 暂停至下次重启只停止不删除；恢复时选 「1」 或 「3」。与 「2」 区别：4 保留容器，2 移除容器

  • 进度如 [+] Running 9/10
  • 数据卷创建：qy-rag_qy_pg_data、qy-rag_minio_data、qy-rag_esdata01 等
  • 容器状态：qy-rag-qy-postgres-1、qy-rag-ragflow-1、qy-rag-qy-es-1 等 Started / Waiting

怎么判断管理操作成功​

所选操作成功的表现
1 随系统开机启动弹出完成提示；http://服务器地址:8513 能打开 RAGFlow
2 关闭随系统启动弹出完成提示；8513 无法访问；docker compose ps 无运行中容器
3 启动或恢复服务弹出完成提示；相关容器为 Up；RAGFlow 可正常访问
4 暂停至下次重启弹出完成提示；8513 暂时不可访问；容器为 Exited（未删除）

常见情况怎么处理​

现象建议操作
8513 打不开先选 「1 随系统开机启动」；仍异常再选 「3 启动或恢复服务」
安装时选了「稍后启动」选 「1 随系统开机启动」
刚改了 QYRAG 的 .env选 「3 启动或恢复服务」
服务器要关机维护选 「4 暂停至下次重启」；维护完再选 「1」
需要彻底停服选 「2 关闭随系统启动」

RAG 更新​

适用场景： 交付包提供了 QYRAG 新版本镜像，需要升级部分或全部组件。

更新会替换所选服务的镜像并重启对应容器。不会自动覆盖 .env 和知识库数据；更新前建议备份 .env，更新 qy-postgres 前须备份数据库。

在 QYRAG 部署目录 执行 ./deploy.sh，选 「3 RAG 更新」。

不要与 NineClaw 更新混淆

QYRAG 更新（本文，五个服务，8513）与 NineClaw 更新（七个服务，8510）是不同目录、不同脚本，菜单相似但切勿混用。

更新流程：

更新图一  主菜单 → 选「3 RAG 更新」
更新图二  勾选要更新的服务 → Enter 开始
         终端：导入镜像（如有）→ 停止并移除容器 → 重新启动
更新图三  「更新完成」→ 核对服务名 → Enter 返回

更新过程与结果​

更新分四步，中间不要关终端：

步骤界面表现你该做什么
1. 选服务更新图二多选列表空格 勾选，Enter 开始
2. 导镜像终端显示「正在导入…」（若有新镜像）等待，不要 Ctrl+C
3. 重启终端显示「局部更新: xxx」、Removed / Started继续等待；8513 可能短暂不可用
4. 看结果「更新完成」对话框核对服务名，Enter 返回

每个勾选的服务，结果通常是下面三种之一：

结果怎么判断下一步
已更新出现在更新图三列表中验证 8513 与 RAGFlow 功能
已跳过未出现在列表中，终端提示跳过检查 docker_images/ 是否有新镜像
失败终端报错，流程中断保留报错，联系交付或运维
更新前准备

建议备份 .env：cp .env .env.bak.$(date +%Y%m%d)。若交付包含新版 docker_images/，请先同步到 QYRAG 部署目录再更新。

RAG 卸载​

适用场景： 不再使用 QYRAG，或需要清空环境后重装。

卸载会停止并移除 QYRAG 相关容器。是否同时删除 .env、数据卷、镜像和网络，由卸载图三决定——操作前请备份。

在 QYRAG 部署目录 执行 ./deploy.sh，选 「4 RAG 卸载」。

不要与 NineClaw 卸载混淆

QYRAG 卸载（本文，8513）与 NineClaw 卸载（8510）互不影响，但务必在 QYRAG 部署目录 执行，不要进错目录。

卸载前请备份

建议备份 .env 与知识库数据：cp .env ~/qyrag-env-backup-$(date +%Y%m%d).bak。数据库、已上传文档等是否需单独导出，请按运维规范或联系交付人员确认。

卸载流程：

卸载图一  主菜单 → 选「4 RAG 卸载」
卸载图二  确认不可逆 → Enter 继续 / ESC 取消
卸载图三  删数据 Enter / 留数据 ESC
卸载图四  终端执行卸载（勿关窗口）
卸载图五  「卸载完成」→ Enter 返回

卸载图一：主菜单，选择「卸载」​

图中可见：

  • 标题 「RAG 部署工具」
  • 当前高亮 「4 RAG 卸载」
  • 底部 <进入 [Enter]>、<退出 [ESC]>

操作： 用 ↑ / ↓ 移到 「4 RAG 卸载」，按 Enter。尚未备份时按 ESC 返回，先完成备份。

卸载图二：确认卸载（不可逆）​

图中可见：

  • 标题 「RAG 卸载」
  • 提示 「即将卸载 RAG，此操作不可逆。」
  • 当前高亮 <继续 [Enter]>，右侧 <取消 [ESC]>
按键作用
Enter继续，进入下一步
ESC取消，返回主菜单

操作： 已备份且确认要卸载 → Enter；误进或未备份 → ESC。

卸载图三：选择是否删除用户数据​

图中可见：

  • 标题 「用户数据」
  • 提问 「是否同时删除用户数据？」
  • 【删除】 将移除 .env、network、volume 及所有相关镜像
  • 【保留】 仅停止并移除容器，数据保留
  • 当前高亮 <删除数据 [Enter]>，右侧 <保留数据 [ESC]>
按键做什么
Enter删除数据：容器、配置、数据卷、镜像一并清除
ESC保留数据：只移除容器，.env 和数据卷留在磁盘
项目删除数据保留数据
容器移除移除
.env / 数据卷 / 镜像删除保留
能否恢复仅能从备份恢复重装后可能沿用原数据

操作： 需要彻底清空 → Enter；暂时停用、以后可能重装 → ESC。选删除前请确认备份可用。

与 NineClaw 同机时

若本机还运行着 NineClaw，共享网络 qiyuan_net 时，删除网络步骤可能跳过或提示被占用——以终端输出为准。卸载 QYRAG 不会自动卸载 NineClaw（8510）。

卸载图四：执行卸载，等待完成​

图中可见（以「删除数据」为例）：

  • 标题 卸载 RAG (删除数据)
  • — 停止并移除容器及数据卷 —：移除 qy-rag-qy-postgres-1、qy-rag-ragflow-1、qy-rag-qy-es-1 等容器，以及 qy-rag_qy_pg_data、qy-rag_minio_data 等数据卷
  • — 删除镜像 —：逐条删除如 pgsty/minio、qy-rag:v0.26.0 等（部分镜像若不存在或被占用可能 跳过）
  • 删除 Docker 网络: qiyuan_net：若本机还运行 NineClaw 并共用该网络，可能显示 跳过（网络仍被 NineClaw 使用）—— 不会卸载 NineClaw
  • 删除 .env：显示 ✓ 已删除

操作： 等待终端输出结束，不要关闭窗口。完成后自动进入卸载图五。

卸载图五：确认卸载完成​

图中可见：

  • 标题 「卸载完成」
  • 删除数据时：✓ RAG 已卸载，数据已清除。
  • 底部 <确认 [Enter]>

若卸载图三选了 保留数据，提示为 ✓ RAG 已卸载。（数据仍在磁盘上）。

操作： 确认文字符合预期后，按 Enter 返回主菜单。

验证卸载结果​

在 QYRAG 部署目录执行：

docker compose ps

成功的表现：

  • 无 QYRAG 相关容器处于 Up（列表为空或提示无服务）
  • 若选择了 删除数据，http://服务器地址:8513 已无法打开
  • 若选择了 保留数据，可用 docker volume ls 查看 qy-rag_* 数据卷是否仍在

卸载后怎么办​

情况怎么做
需要重新安装 QYRAG重新执行本文 RAG 安装 流程；若保留了数据卷，数据是否自动衔接取决于版本与交付说明
仅清理部署目录确认无需要保留的数据后，可删除整个 QYRAG 部署目录（不可恢复）
NineClaw 仍要使用知识库须重新部署 QYRAG，并按 QYRAG 配置 再次对接
误删数据需恢复只能从卸载前的备份恢复；无备份则无法找回

常见问题​

现象可能原因处理
找不到「RAG 安装」章节安装是本文内一节，不是侧边栏单独页面见文首菜单对照表，或点击 RAG 安装
8513 打不开地址/端口错误或服务未启动用服务器真实可达 IP 访问 http://<IP>:8513；执行 docker compose ps；必要时 RAG 管理 → 「1 随系统开机启动」。注意：QYRAG 安装不会询问 NineClaw 那种对外 IP
管理界面标题显示「NineClaw 管理」界面文案与 NineClaw 共用模板只要是在 QYRAG 部署目录 执行的 ./deploy.sh，操作对象仍是 RAG 容器
状态显示「1 个服务」但有多个容器计数指 compose 服务组以 docker compose ps 和 8513 能否访问为准
提示 qiyuan_net 已存在本机已装 NineClaw属正常，继续等待导入完成
镜像导入中断Ctrl+C 或磁盘不足重新 RAG 安装；检查磁盘空间
NineClaw 测试连接失败只完成部署、未做对接，或 Key/地址错误先确认 8513 可访问，再按 QYRAG 配置 操作；确认 Key 为 RAGFlow API Key
8513 与 NineClaw 知识库数量不一致网页登录账号 ≠ API Key 所属账号用生成 Key 的同一账号登录 8513；详见 QYRAG 配置 — 常见问题
误在 NineClaw 目录执行目录搞混确认在 QYRAG 部署目录（含 QYRAG 的 docker-compose.yml）
更新了 QYRAG 但 NineClaw 仍异常混用两套更新QYRAG 更新只影响 8513；NineClaw 见 运维管理
卸载后 NineClaw 仍正常设计如此QYRAG 卸载不影响 NineClaw（8510），但知识库功能会不可用直至重装 QYRAG
