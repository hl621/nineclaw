# ☤ ASCII 视频

将任何内容渲染为彩色 ASCII 字符视频。输入可以是音频、视频、图像、文本或纯数学内容，输出为 MP4/GIF/PNG 序列。默认采用 1080p、24fps，每个字符单元均支持完整 RGB 色彩。无需 GPU。

为 [Hermes Agent](https://github.com/NousResearch/hermes-agent) 构建。可用于任何编程智能体。规范源保存在此处；通过 PR 同步至 [`NousResearch/hermes-agent/skills/creative/ascii-video`](https://github.com/NousResearch/hermes-agent/tree/main/skills/creative/ascii-video)。

## 这是什么

这是一项教智能体从零构建单文件 Python ASCII 视频渲染器的技能。智能体将获得完整流水线：网格系统、字体栅格化、效果库、着色器链、音频分析和并行编码。它编写并运行渲染器，最终获得视频。

输出是真正的视频，而非终端转义码。每一帧均以彩色字符网格计算，通过预栅格化字体位图合成到像素画布上，经着色器后处理后再通过管道传给 ffmpeg。

## 模式

| 模式 | 输入 | 输出 |
|------|-------|--------|
| 视频转 ASCII | 视频文件 | 以 ASCII 重现影像 |
| 音频响应式 | 音频文件 | 由频段、节拍和能量驱动的视觉效果 |
| 生成式 | 无 | 由数学方法生成的程序化动画 |
| 混合式 | 视频 + 音频 | 带音频响应式叠加层的 ASCII 视频 |
| 歌词/文本 | 音频 + 定时文本（SRT） | 带效果的卡拉 OK 风格文本 |
| TTS 旁白 | 文本引语 + API 密钥 | 带打字机文本和生成语音的旁白视频 |

## 流水线

所有模式均遵循相同的 6 阶段流程：

```
INPUT --> ANALYZE --> SCENE_FN --> TONEMAP --> SHADE --> ENCODE
```

1. **输入**加载源素材（生成式模式则无需素材）。
2. **分析**提取逐帧特征。音频分析包括 6 频段 FFT、RMS、频谱质心、平坦度、频谱通量，以及带指数衰减的节拍检测。视频分析包括亮度、边缘和运动。
3. **场景函数**直接返回像素画布。它会合成多个不同密度的字符网格、明度/色相场和像素混合模式。视觉效果在此生成。
4. **色调映射**使用基于百分位数的自适应亮度归一化，并为每个场景设置 gamma。黑底 ASCII 天生偏暗，线性倍增不起作用，而此方法有效。
5. **着色**运行 `ShaderChain`（38 个可组合着色器），并使用 `FeedbackBuffer` 通过空间变换实现时间递归。
6. **编码**通过管道将原始 RGB 帧传给 ffmpeg 进行 H.264 编码。随后拼接片段并混入音频。

## 网格系统

字符渲染在固定尺寸的网格上。叠加多种密度可营造纵深感。

| 尺寸 | 字体 | 1080p 下的网格 | 用途 |
|------|------|---------------|-----|
| xs | 8px | 400x108 | 超高密度数据场 |
| sm | 10px | 320x83 | 雨、星空 |
| md | 16px | 192x56 | 默认均衡设置 |
| lg | 20px | 160x45 | 易读文本 |
| xl | 24px | 137x37 | 大标题 |
| xxl | 40px | 80x22 | 极简巨型元素 |

在 `sm` 和 `lg` 网格上渲染同一场景，再以滤色模式混合，可形成自然的纹理干涉。细节会从粗大字符的间隙中显现。多数场景使用两到三层网格。

## 混合模式与合成

用于叠加画布的 20 种像素混合模式：normal、add、subtract、multiply、screen、overlay、softlight、hardlight、difference、exclusion、colordodge、colorburn、linearlight、vividlight、pin_light、hard_mix、lighten、darken、grain_extract、grain_merge。同时支持 sRGB 和线性光混合。

**反馈缓冲区。** 时间递归——每一帧都会与经过变换的上一帧混合。7 种空间变换：放大、缩小、顺时针/逆时针旋转、上移/下移、镜像。可选逐帧色相偏移以产生彩虹拖尾。每个场景均可配置衰减、混合模式和不透明度。

**遮罩。** 16 种空间合成遮罩：形状遮罩（圆、矩形、圆环、渐变）、程序化遮罩（以任意明度场作为遮罩、文本模板）、动画遮罩（光圈开合、擦除、溶解）、布尔运算（并集、交集、差集、反相）。

**转场。** 交叉淡化、方向擦除、径向擦除、溶解、故障切换。

## 场景设计模式

用于让场景呈现出明确设计意图而非随机感的构图模式。

**图层层级。** 背景（暗淡氛围、高密度网格）、内容（主要视觉、标准网格）、强调（稀疏高光、粗网格）。三者职责分明，而非相互争抢的三个图层。

**方向性参数弧线。** 每个场景的定义性参数会在场景持续期间渐变、加速或逐步累积。基于进度的公式（线性、缓出、阶梯显现）取代漫无目的的 `sin(t)` 振荡。

**场景概念。** 场景围绕视觉隐喻（浮现、下沉、碰撞、熵）构建，并据此选择图层/调色板/反馈，而不是直接以效果命名。

**构图技巧。** 反向旋转的双系统、波浪碰撞、渐进碎裂（Voronoi 单元随时间倍增）、熵（几何形态被反应扩散吞噬）、错落的图层入场（渐强累积）。

## 已知陷阱

**亮度。** ASCII 字符是黑色背景上的细小亮点，大部分帧像素都属于背景。线性 `* N` 倍增会裁剪高光并导致画面泛白。应改用带逐场景 gamma 的 `tonemap()`。默认 gamma 为 0.75，曝光过度场景为 0.55，色调分离场景为 0.50。

**渲染瓶颈。** 用逐单元 Python 循环合成字体位图，每帧约需 100-150ms。不使用 Cython/C 就无法避免。其他所有操作都必须用 numpy 向量化。效果函数中若用 Python for 循环遍历行/列，性能将急剧下降。

**ffmpeg 死锁。** 长时间编码时绝不要使用 `stderr=subprocess.PIPE`。缓冲区在约 64KB 时填满，进程将挂起。应将 stderr 重定向到文件。

**字体单元高度。** Pillow 的 `textbbox()` 在 macOS 上返回错误高度。请用 `font.getmetrics()` 计算 `ascent + descent`。

**字体兼容性。** 并非所有字体都能渲染全部 Unicode 字符。调色板会在初始化时验证，空白字形将被静默移除。
