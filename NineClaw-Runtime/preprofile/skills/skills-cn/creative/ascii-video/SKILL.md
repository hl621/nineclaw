# ASCII 视频制作流水线

## 何时使用

当用户提出以下需求时使用：ASCII 视频、文本艺术视频、终端风格视频、字符艺术动画、复古文本可视化、ASCII 音频可视化器、将视频转换为 ASCII 艺术、矩阵风格效果，或任何 ASCII 动画输出。

## 包含内容

适用于任意格式的 ASCII 艺术视频制作流水线。将视频/音频/图像/生成式输入转换为彩色 ASCII 字符视频输出（MP4、GIF、图像序列）。涵盖：视频转 ASCII、音频响应式音乐可视化、生成式 ASCII 艺术动画、视频+音频响应式混合模式、文本/歌词叠加，以及实时终端渲染。

## 创作标准

这是视觉艺术。ASCII 字符是媒介，电影是标准。

**在编写任何一行代码之前**，先阐明创意概念。情绪是什么？它讲述了怎样的视觉故事？是什么让“这个”项目有别于其他所有 ASCII 视频？用户的提示只是起点——要带着创作野心去诠释，而不是照字面转录。

**首次渲染就必须卓越，没有商量余地。** 输出必须无需多轮修改便具有视觉冲击力。如果成品显得泛泛、扁平，或像“AI 生成的 ASCII 艺术”，那就是错误的——交付前应重新构思创意概念。

**超越参考资料中的现有词汇。** 参考资料里的效果目录、着色器预设和调色板库只是起始词汇。每个项目都应组合、修改并发明新的模式。目录是一组颜料——画作由你来创作。

**主动发挥创意。** 在项目需要时扩展本技能的表达词汇。如果参考资料无法满足愿景，就自行构建。至少加入一个用户未明确要求但会欣赏的视觉时刻——一处转场、一种效果或一个能提升整部作品的色彩选择。

**审美统一重于技术正确。** 视频中的所有场景都必须以统一的视觉语言彼此联结——共享色温、相近的字符调色板、一致的运动词汇。如果视频技术上正确，但每个场景都随机使用完全不同的效果，审美上仍是失败的。

**密集、分层、深思熟虑。** 每一帧都应值得细看。绝不使用平坦的纯黑背景。始终采用多网格合成。始终为每个场景设置变化。始终有意识地运用色彩。

## 技术栈

每个项目使用一个独立、自包含的 Python 脚本。无需 GPU。

| 层 | 工具 | 用途 |
|-------|------|---------|
| 核心 | Python 3.10+、NumPy | 数学、数组操作、向量化效果 |
| 信号 | SciPy | FFT、峰值检测（音频模式） |
| 图像 | Pillow (PIL) | 字体栅格化、帧解码、图像 I/O |
| 视频 I/O | ffmpeg (CLI) | 解码输入、编码输出、混入音频 |
| 并行 | concurrent.futures | 用 N 个工作进程批量/分片渲染 |
| TTS | ElevenLabs API（可选） | 生成旁白片段 |
| 可选 | OpenCV | 视频帧采样、边缘检测 |

## 流水线架构

所有模式均遵循相同的 6 阶段流水线：

```
INPUT → ANALYZE → SCENE_FN → TONEMAP → SHADE → ENCODE
```

1. **INPUT**——加载/解码源素材（视频帧、音频采样、图像，或无素材）
2. **ANALYZE**——提取逐帧特征（音频频段、视频亮度/边缘、运动向量）
3. **SCENE_FN**——场景函数渲染到像素画布（`uint8 H,W,3`）。通过 `_render_vf()` + 像素混合模式合成多个字符网格。参见 `references/composition.md`
4. **TONEMAP**——基于百分位数的自适应亮度归一化。参见 `references/composition.md` § 自适应色调映射
5. **SHADE**——通过 `ShaderChain` + `FeedbackBuffer` 进行后处理。参见 `references/shaders.md`
6. **ENCODE**——通过管道将原始 RGB 帧传给 ffmpeg，进行 H.264/GIF 编码

### 分区变化

绝不要让整段视频使用同一套配置。对于每个区段/场景：
- **使用不同的背景效果**（或组合 2-3 种）
- **使用不同的字符调色板**（与情绪匹配）
- **使用不同的色彩策略**（或至少使用不同色相）
- **改变着色器强度**（高潮时增加泛光，安静时增加颗粒）
- 如果启用了粒子，**使用不同的粒子类型**

## 工作流程

### 第 1 步：创意愿景

编写代码之前，先阐明创意概念：

- **情绪/氛围**：希望观众感受到什么？充满活力、冥想般宁静、混沌、优雅，还是不祥？
- **视觉故事**：整个时段会发生什么？积蓄张力？变形？消解？
- **色彩世界**：暖色/冷色？单色？霓虹？大地色？主导色相是什么？
- **字符质感**：密集数据？稀疏星点？有机圆点？几何方块？
- **是什么让“这个”项目不同**：令项目独一无二的那一点是什么？
- **情绪弧线**：场景如何推进？以活力开场，逐步走向高潮，再归于平静？

将用户提示映射为审美选择。“放松的 lo-fi 可视化器”所需要的一切，都应不同于“故障风赛博朋克数据流”。

### 第 2 步：技术设计

- **模式**——从上述 6 种模式中选择
- **分辨率**——横向 1920x1080（默认）、纵向 1080x1920、方形 1080x1080 @ 24fps
- **硬件检测**——自动检测核心数/RAM，并设置质量配置。参见 `references/optimization.md`
- **区段**——将时间戳映射至场景函数，每个场景都拥有自己的效果/调色板/色彩/着色器配置
- **输出格式**——MP4（默认）、GIF（640x360 @ 15fps）、PNG 序列

### 第 3 步：构建脚本

使用单个 Python 文件。组件（附参考资料）：

1. **硬件检测 + 质量配置**——`references/optimization.md`
2. **输入加载器**——取决于模式；`references/inputs.md`
3. **特征分析器**——音频 FFT、视频亮度或合成特征
4. **网格 + 渲染器**——带位图缓存的多密度网格；`references/architecture.md`
5. **字符调色板**——每个项目使用多套；`references/architecture.md` § 调色板
6. **色彩系统**——HSV + 离散 RGB + 色彩和谐方案生成；`references/architecture.md` § 色彩
7. **场景函数**——每个函数返回 `canvas (uint8 H,W,3)`；`references/scenes.md`
8. **色调映射**——自适应亮度归一化；`references/composition.md`
9. **着色器流水线**——`ShaderChain` + `FeedbackBuffer`；`references/shaders.md`
10. **场景表 + 分派器**——时间 → 场景函数 + 配置；`references/scenes.md`
11. **并行编码器**——使用 ffmpeg 管道，由 N 个工作进程渲染片段
12. **主函数**——编排完整流水线

### 第 4 步：质量验证

- **先测试帧**：完整渲染之前，先渲染关键时间戳处的单帧
- **亮度检查**：所有 ASCII 内容均应满足 `canvas.mean() > 8`。若过暗，请降低 gamma
- **视觉连贯性**：所有场景是否让人感觉属于同一部视频？
- **创意愿景检查**：输出是否符合第 1 步的概念？如果看起来千篇一律，就返回重做

## 关键实现说明

### 亮度——使用 `tonemap()`，不要使用线性倍增

这是首要视觉问题。黑底 ASCII 天生偏暗。**绝不要使用 `canvas * N` 倍增**——这会裁剪高光。请使用自适应色调映射：

```python
def tonemap(canvas, gamma=0.75):
    f = canvas.astype(np.float32)
    lo, hi = np.percentile(f[::4, ::4], [1, 99.5])
    if hi - lo < 10: hi = lo + 10
    f = np.clip((f - lo) / (hi - lo), 0, 1) ** gamma
    return (f * 255).astype(np.uint8)
```

流水线：`scene_fn() → tonemap() → FeedbackBuffer → ShaderChain → ffmpeg`

逐场景 gamma：默认 0.75，曝光过度场景 0.55，色调分离场景 0.50，明亮场景 0.85。暗色图层应使用 `screen` 混合（而非 `overlay`）。

### 字体单元高度

macOS Pillow：`textbbox()` 返回错误高度。请使用 `font.getmetrics()`：`cell_height = ascent + descent`。参见 `references/troubleshooting.md`。

### ffmpeg 管道死锁

长时间运行 ffmpeg 时绝不要使用 `stderr=subprocess.PIPE`——缓冲区会在 64KB 时填满并造成死锁。应重定向到文件。参见 `references/troubleshooting.md`。

### 字体兼容性

并非所有字体都能渲染全部 Unicode 字符。初始化时应验证调色板——渲染每个字符并检查是否为空白输出。参见 `references/troubleshooting.md`。

### 按片段架构

对于分段视频（引语、场景、章节），将每一段渲染为单独的片段文件，以便并行渲染和选择性重新渲染。参见 `references/scenes.md`。

## 创意发散（仅当用户要求实验性/创意性/独特输出时使用）

如果用户要求创意、实验性、出人意料或非传统的输出，请选出最契合的策略，并在生成代码**之前**推演其步骤。

- **强制联想**——用户希望获得跨领域灵感时（“让它看起来有机”“工业美学”）
- **概念融合**——用户点名要组合两种事物时（“海洋遇见音乐”“太空 + 书法”）
- **斜向策略**——用户最大程度保持开放时（“给我惊喜”“我从未见过的东西”）

### 强制联想
1. 选择一个与视觉目标无关的领域（天气系统、微生物学、建筑、流体力学、织物编织）
2. 列出其核心视觉/结构元素（侵蚀 → 逐渐显现；有丝分裂 → 分裂复制；编织 → 交错图案）
3. 将这些元素映射到 ASCII 字符和动画模式
4. 综合——“侵蚀”或“结晶”在字符网格中是什么样子？

### 概念融合
1. 指定两个不同的视觉/概念空间（例如海浪 + 乐谱）
2. 映射对应关系（波峰 = 高音，波谷 = 休止符，泡沫 = 断奏）
3. 选择性融合——保留最有趣的映射，舍弃生硬牵强的映射
4. 发展仅存在于融合体中的涌现属性

### 斜向策略
1. 抽取一条：“将错误视作隐藏的意图并予以尊重” / “使用一个旧想法” / “你最亲近的朋友会怎么做？” / “强调缺陷” / “将它上下颠倒” / “只取一部分，而非整体” / “反转”
2. 结合当前 ASCII 动画挑战解读该指令
3. 编写代码前，将这种横向洞见应用于视觉设计
