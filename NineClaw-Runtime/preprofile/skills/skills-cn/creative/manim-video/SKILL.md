# Manim 视频制作流水线

## 何时使用

当用户请求以下内容时使用：动画讲解、数学动画、概念可视化、算法演示、技术科普、3Blue1Brown 风格视频，或任何包含几何/数学内容的程序化动画。使用 Manim Community Edition 创建 3Blue1Brown 风格的讲解视频、算法可视化、方程推导、架构图和数据故事。

## 创作标准

这是教育电影。每一帧都在教学。每一个动画都在揭示结构。

**在编写任何一行代码之前**，先清晰阐明叙事弧线。它要纠正什么误解？“顿悟时刻”是什么？怎样的视觉故事能带领观众从困惑走向理解？用户的提示只是起点——要以教学上的雄心来解读它。

**先几何，后代数。** 先展示形状，再展示方程。视觉记忆的编码速度快于符号记忆。当观众先看到几何模式、再看到公式时，方程便显得水到渠成。

**首轮渲染就必须卓越，这一点不容妥协。** 输出必须无需多轮修改就做到视觉清晰、审美统一。如果画面显得杂乱、节奏不佳，或像“AI 生成的幻灯片”，那就是错误的。

**透明度分层用于引导注意力。** 绝不要让所有内容都以最高亮度显示。主要元素为 1.0，语境元素为 0.4，结构元素（坐标轴、网格）为 0.15。大脑会分层处理视觉显著性。

**留出呼吸空间。** 每个动画之后都需要 `self.wait()`。观众需要时间消化刚刚出现的内容。绝不要从一个动画匆忙切换到下一个。关键揭示之后停顿 2 秒，绝不是浪费。

**统一的视觉语言。** 所有场景应共享同一套配色、统一的字号体系和一致的动画速度。一个技术上正确、但每个场景都随意使用不同颜色的视频，在审美上是失败的。

## 前置条件

运行 `scripts/setup.sh` 验证所有依赖项。要求：Python 3.10+、Manim Community Edition v0.20+（`pip install manim`）、LaTeX（Linux 上使用 `texlive-full`，macOS 上使用 `mactex`）以及 ffmpeg。参考文档已针对 Manim CE v0.20.1 完成测试。

## 技术栈

每个项目使用单个 Python 脚本。无需浏览器、Node.js 或 GPU。

| 层级 | 工具 | 用途 |
|-------|------|---------|
| 核心 | Manim Community Edition | 场景渲染、动画引擎 |
| 数学 | LaTeX (texlive/MiKTeX) | 通过 `MathTex` 渲染方程 |
| 视频 I/O | ffmpeg | 场景拼接、格式转换、音频混流 |
| TTS | ElevenLabs / Qwen3-TTS（可选） | 旁白配音 |

## 流水线

```
PLAN --> CODE --> RENDER --> STITCH --> AUDIO (optional) --> REVIEW
```

1. **规划** — 编写 `plan.md`，包含叙事弧线、场景列表、视觉元素、配色方案和旁白脚本
2. **编码** — 编写 `script.py`，每个场景对应一个类，并且每个场景都可独立渲染
3. **渲染** — 草稿使用 `manim -ql script.py Scene1 Scene2 ...`，成片使用 `-qh`
4. **拼接** — 使用 ffmpeg concat 将场景片段拼接为 `final.mp4`
5. **音频**（可选）— 通过 ffmpeg 添加旁白和/或背景音乐。参阅 `references/rendering.md`
6. **审查** — 渲染预览静帧，对照计划验证并进行调整

## 项目结构

```
project-name/
  plan.md                # Narrative arc, scene breakdown
  script.py              # All scenes in one file
  concat.txt             # ffmpeg scene list
  final.mp4              # Stitched output
  media/                 # Auto-generated by Manim
    videos/script/480p15/
```

## 创作指导

### 配色方案

| 配色 | 背景 | 主色 | 辅色 | 强调色 | 使用场景 |
|---------|-----------|---------|-----------|--------|----------|
| **经典 3B1B** | `#1C1C1C` | `#58C4DD` (BLUE) | `#83C167` (GREEN) | `#FFFF00` (YELLOW) | 通用数学/计算机科学 |
| **温暖学术风** | `#2D2B55` | `#FF6B6B` | `#FFD93D` | `#6BCB77` | 亲切易懂的内容 |
| **霓虹科技风** | `#0A0A0A` | `#00F5FF` | `#FF00FF` | `#39FF14` | 系统、架构 |
| **单色风** | `#1A1A2E` | `#EAEAEA` | `#888888` | `#FFFFFF` | 极简风格 |

### 动画速度

| 情境 | run_time | 之后的 self.wait() |
|---------|----------|-------------------|
| 标题/开场出现 | 1.5s | 1.0s |
| 关键方程揭示 | 2.0s | 2.0s |
| 变换/形变 | 1.5s | 1.5s |
| 辅助标签 | 0.8s | 0.5s |
| FadeOut 清场 | 0.5s | 0.3s |
| “顿悟时刻”揭示 | 2.5s | 3.0s |

### 字体层级

| 角色 | 字号 | 用法 |
|------|-----------|-------|
| 标题 | 48 | 场景标题、开场文字 |
| 标头 | 36 | 场景内的章节标题 |
| 正文 | 30 | 讲解文字 |
| 标签 | 24 | 标注、坐标轴标签 |
| 说明文字 | 20 | 字幕、细则文字 |

### 字体

**所有文字都使用等宽字体。** Manim 的 Pango 渲染器在所有字号下使用比例字体都会产生异常的字距调整。完整建议请参阅 `references/visual-design.md`。

```python
MONO = "Menlo"  # define once at top of file

Text("Fourier Series", font_size=48, font=MONO, weight=BOLD)  # titles
Text("n=1: sin(x)", font_size=20, font=MONO)                  # labels
MathTex(r"\nabla L")                                            # math (uses LaTeX)
```

为保证可读性，`font_size=18` 是最小值。

### 各场景的变化

绝不要让所有场景使用完全相同的配置。每个场景都应做到：
- **不同的主导色**——从配色方案中选取
- **不同的布局**——不要总是让所有内容居中
- **不同的入场动画**——在 Write、FadeIn、GrowFromCenter、Create 之间变换
- **不同的视觉权重**——有些场景信息密集，有些则留白充足

## 工作流程

### 第 1 步：规划（plan.md）

编写任何代码之前，先创建 `plan.md`。完整模板请参阅 `references/scene-planning.md`。

### 第 2 步：编码（script.py）

每个场景对应一个类。每个场景都可独立渲染。

```python
from manim import *

BG = "#1C1C1C"
PRIMARY = "#58C4DD"
SECONDARY = "#83C167"
ACCENT = "#FFFF00"
MONO = "Menlo"

class Scene1_Introduction(Scene):
    def construct(self):
        self.camera.background_color = BG
        title = Text("Why Does This Work?", font_size=48, color=PRIMARY, weight=BOLD, font=MONO)
        self.add_subcaption("Why does this work?", duration=2)
        self.play(Write(title), run_time=1.5)
        self.wait(1.0)
        self.play(FadeOut(title), run_time=0.5)
```

关键模式：
- **每个动画都配字幕**：使用 `self.add_subcaption("text", duration=N)`，或使用 `subcaption="text"` 参数（位于 `self.play()` 上）
- **共享颜色常量**：将其放在文件顶部，以保证跨场景一致性
- **`self.camera.background_color`**：在每个场景中设置
- **干净利落的退场**——在场景结束时 FadeOut 所有 mobject：`self.play(FadeOut(Group(*self.mobjects)))`

### 第 3 步：渲染

```bash
manim -ql script.py Scene1_Introduction Scene2_CoreConcept  # draft
manim -qh script.py Scene1_Introduction Scene2_CoreConcept  # production
```

### 第 4 步：拼接

```bash
cat > concat.txt << 'EOF'
file 'media/videos/script/480p15/Scene1_Introduction.mp4'
file 'media/videos/script/480p15/Scene2_CoreConcept.mp4'
EOF
ffmpeg -y -f concat -safe 0 -i concat.txt -c copy final.mp4
```

### 第 5 步：审查

```bash
manim -ql --format=png -s script.py Scene2_CoreConcept  # preview still
```

## 关键实现注意事项

### 为 LaTeX 使用原始字符串
```python
# WRONG: MathTex("\frac{1}{2}")
# RIGHT:
MathTex(r"\frac{1}{2}")
```

### 边缘文字须满足 buff >= 0.5
```python
label.to_edge(DOWN, buff=0.5)  # never < 0.5
```

### 替换文字前先 FadeOut
```python
self.play(ReplacementTransform(note1, note2))  # not Write(note2) on top
```

### 绝不要为尚未添加的 Mobject 设置动画
```python
self.play(Create(circle))  # must add first
self.play(circle.animate.set_color(RED))  # then animate
```

## 创意发散（仅当用户请求实验性/创意性/独特输出时使用）

如果用户要求采用富有创意、实验性或非常规的讲解方式，请先选择一种策略并进行推理，**然后再**设计动画。

- **SCAMPER**——当用户希望用全新方式讲解标准主题时使用
- **假设反转**——当用户希望挑战某个主题的传统教学方式时使用

### SCAMPER 转换法
选取一个标准的数学/技术可视化并对其进行转换：
- **替代**：替换标准视觉隐喻（数轴 → 蜿蜒路径，矩阵 → 城市网格）
- **组合**：融合两种讲解方式（同时使用代数方式和几何方式）
- **反转**：反向推导——从结果出发，逐步拆解至公理
- **修改**：夸大某个参数，以展示其重要性（10 倍学习率、1000 倍样本量）
- **消除**：移除所有符号——仅通过动画和空间关系进行讲解

### 假设反转
1. 列出该主题在可视化方式上的“标准”做法（从左到右、2D、离散步骤、形式化符号）
2. 选择最根本的假设
3. 将其反转（从右到左推导、将 2D 概念嵌入 3D、以连续形变取代分步过程、完全不使用符号）
4. 探索这种反转揭示了哪些标准方法所掩盖的内容
