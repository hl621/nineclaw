# 会议论文核对清单

本文档汇总了主要 ML/AI 会议的强制性论文核对清单要求。如今各大会议均要求提交论文核对清单；缺少清单会导致论文未经评审即被拒稿。

## NeurIPS 论文核对清单

### 强制组成部分

所有 NeurIPS 投稿都必须附上填写完整的论文核对清单。缺少该项的论文会被**直接拒稿**。清单置于参考文献和补充材料之后，不计入页数限制。

### 16 项必答内容

#### 1. 主张与结果一致
作者必须确认摘要和引言中的主张与理论及实验结果一致，并清楚陈述贡献、假设和局限性。

**核对内容：**
- [ ] 摘要中的主张与实际结果一致
- [ ] 引言没有夸大结论
- [ ] 贡献具体且可证伪

#### 2. 局限性讨论
论文应设置专门的“局限性”一节，说明较强假设、违反假设时的稳健性、适用范围限制，以及影响性能的各项因素。

**应包含：**
- [ ] 单独的“局限性”一节
- [ ] 对适用范围的如实评估
- [ ] 方法可能失效的条件

#### 3. 理论与证明
涉及理论贡献的论文必须完整陈述所有假设，并提供完整证明；证明可置于正文或附录，正文中应给出有助于直观理解的证明概要。

**核对内容：**
- [ ] 所有假设均有形式化表述
- [ ] 提供完整证明（正文或附录）
- [ ] 正文中提供有助于直观理解的证明概要

#### 4. 可复现性
作者必须说明为确保结果可验证而采取的措施，例如发布代码、提供详细说明、开放模型访问或提供检查点；具体形式应与论文贡献类型相符。

**应提供：**
- [ ] 清晰的可复现性声明
- [ ] 代码可用性信息
- [ ] 模型检查点（如适用）

#### 5. 数据与代码访问
应通过补充材料或 URL 提供复现主要实验结果的说明，包括精确命令和环境规格。

**应包含：**
- [ ] 运行实验的精确命令
- [ ] 环境规格（requirements.txt、conda env）
- [ ] 数据访问说明

#### 6. 实验细节
论文必须在正文或补充材料中说明训练细节，包括数据集划分、超参数和选择方法。

**应记录：**
- [ ] 训练集／验证集／测试集的划分细节
- [ ] 使用的全部超参数
- [ ] 超参数选择方法

#### 7. 统计显著性
结果必须提供误差条、置信区间或统计检验，并明确说明计算方法及其基础假设。

**应包含：**
- [ ] 误差条或置信区间
- [ ] 运行次数／随机种子数
- [ ] 计算方法（标准差或标准误）

#### 8. 计算资源
应说明计算设备类型（CPU/GPU）、内存、存储空间、单次运行时间，以及整个项目所需的总计算量。

**应记录：**
- [ ] GPU 类型和数量
- [ ] 每次运行的训练时间
- [ ] 使用的总计算量

#### 9. 遵守伦理准则
作者须确认遵守 NeurIPS Code of Ethics，并说明任何确有必要的偏离之处。

**核对内容：**
- [ ] 阅读 NeurIPS Code of Ethics
- [ ] 确认遵守准则
- [ ] 说明任何偏离及其理由

#### 10. 广泛影响
如适用，应讨论潜在的负面社会用途、公平性问题、隐私风险及可能的缓解措施。

**应讨论：**
- [ ] 潜在负面用途
- [ ] 公平性考量
- [ ] 隐私影响
- [ ] 缓解措施

#### 11. 安全保障
高风险模型（如语言模型）和从互联网抓取的数据集需要受控发布机制及使用指南。

**应考虑：**
- [ ] 敏感模型的发布策略
- [ ] 必要时提供使用指南
- [ ] 适当时设置访问控制

#### 12. 尊重许可条款
使用任何已有资产时，都必须引用其创建者，注明许可证名称、URL、版本号，并确认相关服务条款。

**应记录：**
- [ ] 引用数据集许可证
- [ ] 遵守代码许可证
- [ ] 注明版本号

#### 13. 资产文档
新发布的数据集或模型需使用结构化模板，记录训练细节、局限性、知情同意流程和许可信息。

**针对新数据集／模型：**
- [ ] 数据表或模型卡
- [ ] 训练数据文档
- [ ] 已知局限性

#### 14. 人类受试者
众包研究必须提供参与者说明、截图和报酬细节，并满足最低工资要求。

**应包含：**
- [ ] 任务说明
- [ ] 报酬细节
- [ ] 用时估算

#### 15. IRB 批准
涉及人类受试者的研究必须取得机构审查委员会批准或同等审批，并披露风险说明；投稿时仍须保持匿名。

**核对内容：**
- [ ] 已取得 IRB 批准
- [ ] 已完成风险评估
- [ ] 投稿时已匿名化

#### 16. LLM 声明
如果大语言模型是核心方法的一部分，则必须披露；仅将其用于写作或编辑，无需声明。

**应披露：**
- [ ] LLM 是否作为核心方法的一部分
- [ ] LLM 的具体使用方式
- [ ]（写作辅助无需披露）

### 回答格式

作者须为每个问题选择“是”“否”或“不适用”，并可附上 1-2 句说明。

**重要提示：** NeurIPS 明确要求评审不得因作者如实承认局限性而扣分。

## ICML 论文核对清单

### 广泛影响声明

ICML 要求在论文末尾、参考文献之前加入“广泛影响声明”。该声明不计入页数限制。

**必备内容：**
- 潜在正面影响
- 潜在负面影响
- 缓解措施
- 可能受到影响的群体

### ICML 特定要求

#### 可复现性核对清单

- [ ] 清楚说明数据集划分
- [ ] 列出超参数
- [ ] 记录搜索范围
- [ ] 解释选择方法
- [ ] 说明计算资源
- [ ] 说明代码可用性

#### 统计结果报告

- [ ] 所有图中均提供误差条
- [ ] 明确使用标准差还是标准误
- [ ] 说明运行次数
- [ ] 比较方法时进行显著性检验

#### 匿名化

- [ ] 论文中不出现作者姓名
- [ ] 不包含致谢
- [ ] 不包含资助编号
- [ ] 以第三人称引用自己的既有工作
- [ ] 不包含可识别作者身份的代码仓库 URL

## ICLR 要求

### LLM 披露政策（2026 年新增）

ICLR 对 LLM 的使用有明确披露要求：

> “如果 LLM 在研究构思和／或写作中发挥了重要作用，达到可被视为贡献者的程度，作者必须在单独的附录章节中准确说明其作用。”

**以下情况需要披露：**
- 使用 LLM 进行重要的研究构思
- 使用 LLM 完成大量写作
- LLM 可被视为贡献者

**以下情况无需披露：**
- 语法检查
- 少量编辑辅助
- 代码补全工具

**不披露的后果：**
- 直接拒稿
- 论文发表后可能产生问题

### ICLR 特定要求

#### 可复现性声明（可选但建议提供）

添加声明，并说明：
- 支持材料
- 代码可用性
- 数据可用性
- 模型检查点

#### 伦理声明（可选）

用不超过 1 页的篇幅说明潜在问题，不计入页数限制。

#### 对等审稿义务

- 在 3 篇或以上论文中署名的作者必须审阅至少 6 篇论文
- 每篇投稿至少须有 1 名作者注册审阅至少 3 篇论文

## ACL 要求

### 局限性一节（强制）

ACL 明确要求论文包含“局限性”一节：

**应包含：**
- 所采用的强假设
- 适用范围限制
- 方法可能失效的情形
- 泛化方面的顾虑

**重要提示：** “局限性”一节不计入页数限制。

### ACL 特定核对清单

#### 负责任的 NLP

- [ ] 讨论偏见问题
- [ ] 在适用情况下评估公平性
- [ ] 讨论双重用途风险

#### 多语言考量

如适用：
- [ ] 考虑语言多样性
- [ ] 纳入非英语语言
- [ ] 核验翻译质量

#### 人工评估

如适用：
- [ ] 提供标注人员信息
- [ ] 报告一致性指标
- [ ] 记录报酬情况

<a id="aaai-requirements"></a>

## AAAI 要求

### 格式（各会议中最严格）

在各大会议中，AAAI 对格式规则的执行最为严格。偏离模板的论文会被直接拒稿。

- [ ] 使用未经修改的**原版** AAAI 样式文件——不得使用 `\setlength`，不得用 `\vspace` 取巧，不得覆盖字体设置
- [ ] 正文 7 页（终稿加入作者信息后为 8 页）
- [ ] 双栏格式，Times 字体（由模板设置）
- [ ] 参考文献和附录不计入页数限制
- [ ] 摘要必须只有一个段落
- [ ] 不得修改页边距、栏宽或字号

### 必备章节

- [ ] 摘要（单段，不含数学公式或引文）
- [ ] 引言，其中明确陈述论文贡献
- [ ] 按 AAAI 格式编排的参考文献（使用 `aaai2026.bst`）
- [ ] 附录（可选，不限篇幅）

### 伦理与可复现性

- [ ] 广泛影响声明（鼓励提供，但并非始终强制——查看当年征稿通知）
- [ ] 可复现性细节（数据集、代码可用性）
- [ ] 如适用，声明使用 AI 写作工具

### 与其他会议的主要区别

- **不强制设置单独的局限性一节**（不同于 ACL），但建议讨论局限性
- **格式审查最严格**——样式检查器会拒绝不合规的 PDF
- **没有 NeurIPS 式的论文核对清单**，但仍应使用下方的通用清单
- **统一模板**在同一个文件中包含正文和补充材料

<a id="colm-requirements"></a>

## COLM 要求

### 概述

COLM（Conference on Language Modeling）专注于语言模型研究。论文的问题设定和论述方式必须面向该研究社群。

### 格式

- [ ] 正文 9 页（终稿 10 页）
- [ ] 使用 COLM 模板（基于 ICLR 模板修改而成）
- [ ] 双盲评审
- [ ] 参考文献和附录不限篇幅

### 必备章节

- [ ] 摘要
- [ ] 面向语言建模社群撰写的引言
- [ ] 结论
- [ ] 参考文献

### 内容要求

- [ ] 贡献必须与语言模型相关（广义上包括训练、评估、应用、理论、对齐和安全）
- [ ] 如果方法具有通用性，应使用语言模型示例来组织论述
- [ ] 在适用情况下，基线应包含近期针对 LM 的方法

### 与其他会议的主要区别

- **范围比 NeurIPS/ICML 更窄**——必须面向 LM 社群组织论述
- **模板源自 ICLR**——格式规则相近
- **创办时间较短**——评审惯例仍在形成，评估宜尽量充分
- **没有 NeurIPS 式的强制核对清单**，但通常应讨论广泛影响
- **LLM 披露**：若在研究中使用 LLM（包括代码生成、数据标注、写作辅助），应予披露

<a id="universal-pre-submission-checklist"></a>

## 通用投稿前核对清单

### 每次投稿前

#### 论文内容

- [ ] 摘要未超过字数限制（通常为 250-300 词）
- [ ] 正文未超过页数限制
- [ ] 参考文献完整且已经核验
- [ ] 已包含局限性一节
- [ ] 所有图表均有图注或表注
- [ ] 图注和表注不依赖正文即可理解

#### 格式

- [ ] 使用正确的模板（对应会议和年份）
- [ ] 未修改页边距
- [ ] 未修改字号
- [ ] 满足双盲要求
- [ ] 按要求设置页码：评审稿保留页码，终稿不显示页码

#### 技术内容

- [ ] 所有主张均有证据支持
- [ ] 已包含误差条
- [ ] 基线选择恰当
- [ ] 已记录超参数
- [ ] 已说明计算资源

#### 可复现性

- [ ] 将提供代码（或说明无法提供的理由）
- [ ] 将提供数据（或说明无法提供的理由）
- [ ] 已记录运行环境
- [ ] 已提供复现命令

#### 伦理

- [ ] 已考虑广泛影响
- [ ] 如实陈述局限性
- [ ] 遵守许可证条款
- [ ] 必要时已取得 IRB 批准

#### 最终检查

- [ ] PDF 编译无误
- [ ] 所有图形均正确渲染
- [ ] 所有引文均能正确解析
- [ ] 补充材料组织有序
- [ ] 已填写会议核对清单

## 速查：页数限制

| 会议 | 正文 | 参考文献 | 附录 |
|------------|-------------|------------|----------|
| NeurIPS 2025 | 9 页 | 不限 | 不限（核对清单单列） |
| ICML 2026 | 8 页（终稿 +1 页） | 不限 | 不限 |
| ICLR 2026 | 9 页（终稿 +1 页） | 不限 | 不限 |
| ACL 2025 | 8 页（长文） | 不限 | 不限 |
| AAAI 2026 | 7 页（终稿 +1 页） | 不限 | 不限 |
| COLM 2025 | 9 页（终稿 +1 页） | 不限 | 不限 |

## 模板位置

所有会议模板均位于 `templates/` 目录：

```
templates/
├── icml2026/       # ICML 2026 official
├── iclr2026/       # ICLR 2026 official
├── neurips2025/    # NeurIPS 2025
├── acl/            # ACL style files
├── aaai2026/       # AAAI 2026
└── colm2025/       # COLM 2025
```
