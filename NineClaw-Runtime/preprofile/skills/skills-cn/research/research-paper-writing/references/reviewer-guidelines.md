## 通用评估维度

所有主要的机器学习会议都会从四个核心维度评估论文：

### 1. 质量（技术可靠性）

**审稿人会问：**
- 理论分析或实验结果是否充分支持论文的主张？
- 证明是否正确？实验是否设置了恰当的控制条件？
- 基线是否合适，比较是否公平？
- 研究方法是否合理？

**如何确保高质量：**
- 提供完整的证明（可放在正文中，也可在附录中给出并在正文中提供证明概要）
- 使用恰当的基线（而非刻意选取的弱基线）
- 报告方差或误差线，并说明计算方法
- 记录超参数的选择过程

### 2. 清晰度（写作与组织）

**审稿人会问：**
- 论文写作是否清晰、组织是否合理？
- 该领域的专家能否复现结果？
- 符号是否一致？术语是否均有定义？
- 论文是否自成一体？

**如何确保表述清晰：**
- 全文使用一致的术语
- 所有符号都在首次出现时定义
- 提供复现所需的详细信息（可放入附录）
- 投稿前请非作者通读论文

### 3. 重要性（影响力与意义）

**审稿人会问：**
- 研究结果是否会对学术共同体产生重要影响？
- 其他研究者是否会在这项工作的基础上继续推进？
- 论文是否解决了一个重要问题？
- 研究成果在现实世界中可能产生怎样的影响？

**如何体现重要性：**
- 清晰阐明问题的重要性
- 将工作与更广泛的研究主题联系起来
- 讨论潜在应用
- 与现有方法进行有实质意义的比较

### 4. 原创性（新颖性与贡献）

**审稿人会问：**
- 这项工作是否提供了新的见解？
- 它与先前工作有何不同？
- 其贡献是否并非微不足道？

**NeurIPS 指南中的关键观点：**
> “原创性并不一定要求提出一种全新的方法。通过评估现有方法获得新见解，或阐明某些方法为何成功的论文，同样可以具有很强的原创性。”

## NeurIPS 审稿人指南

### 评分体系（1–6 分）

| 分数 | 评级 | 说明 |
|-------|-------|-------------|
| **6** | 强烈接收 | 突破性且无明显缺陷的工作；位列全部投稿的前 2–3% |
| **5** | 接收 | 技术扎实、影响力大；会使学术共同体受益 |
| **4** | 边缘接收 | 工作扎实，但评估有限；倾向接收 |
| **3** | 边缘拒绝 | 工作扎实，但缺点超过优点；倾向拒绝 |
| **2** | 拒绝 | 存在技术缺陷或评估薄弱 |
| **1** | 强烈拒绝 | 结果已广为人知，或伦理问题未得到处理 |

### 对审稿人的要求

审稿人被明确要求：

1. **以论文当前呈现的内容为准进行评估**——而不是评估论文经过修改后可能达到的水平
2. **提供建设性反馈**——给出 3–5 条可付诸行动的意见
3. **不因作者坦诚说明局限性而扣分**——鼓励作者承认不足
4. **评估可复现性**——这项工作能否得到验证？
5. **考虑伦理影响**——是否可能被滥用或造成伤害

### 审稿人应避免的做法

- 给出肤浅或缺乏专业依据的评审
- 要求不合理的额外实验
- 因作者坦诚承认局限性而予以惩罚
- 因论文没有引用审稿人自己的工作而拒稿

### 时间安排（NeurIPS 2025——请核实当年日期）

- 认领意向期：5 月 17–21 日
- 审稿期：5 月 29 日至 7 月 2 日
- 作者答辩期：7 月 24–30 日
- 讨论期：7 月 31 日至 8 月 13 日
- 最终结果通知：9 月 18 日

> **注意**：以上日期来自 2025 年的会议周期。请务必前往会议官网查看当年的征稿通知。

<a id="icml-reviewer-guidelines"></a>

## ICML 审稿人指南

### 评审结构

ICML 审稿人需要提供：

1. **摘要**——简要说明论文贡献
2. **优点**——论文的积极方面
3. **缺点**——有待改进之处
4. **问题**——需要作者澄清的事项
5. **局限性**——对论文所述局限性的评估
6. **伦理**——任何相关疑虑
7. **总体评分**——审稿建议

### 评分指南

ICML 采用类似的 1–6 分制，并按以下标准校准：
- 已接收论文中的前 25%：5–6 分
- 典型的已接收论文：4–5 分
- 边缘论文：3–4 分
- 明确应拒绝的论文：1–2 分

### 关键评估要点

1. **可复现性**——是否提供了足够的细节？
2. **实验严谨性**——是否使用多个随机种子和恰当的基线？
3. **写作质量**——表达是否清晰，组织是否有条理，结构是否合理？
4. **新颖性**——贡献是否并非微不足道？

<a id="iclr-reviewer-guidelines"></a>

## ICLR 审稿人指南

### OpenReview 流程

ICLR 使用 OpenReview，具有以下特点：
- 评审意见会在录用决定公布后公开
- 审稿人可以看到作者回复
- 审稿人与 AC 之间可以展开讨论

### 评分

ICLR 评审包含：
- **可靠性**：1–4 分
- **表述质量**：1–4 分
- **贡献**：1–4 分
- **总体评分**：1–10 分
- **置信度**：1–5 分

### ICLR 的特殊考量

1. **LLM 使用披露**——审稿人会评估论文是否恰当披露了 LLM 的使用情况
2. **可复现性**——强调代码的可获取性
3. **互惠审稿**——作者也必须承担审稿工作

<a id="acl-reviewer-guidelines"></a>

## ACL 审稿人指南

### ACL 特有的标准

ACL 在通用标准之外还采用 NLP 特有的评估标准：

1. **语言学可靠性**——语言学相关主张是否准确？
2. **资源文档**——数据集和模型是否得到妥善记录？
3. **多语言考量**——如适用，是否考虑了语言多样性？

### 局限性章节

ACL 明确要求论文包含“局限性”章节。审稿人会检查：
- 对局限性的说明是否坦诚且全面？
- 这些局限性是否会削弱论文的核心主张？
- 是否讨论了潜在的负面影响？

### 伦理审查

ACL 针对以下问题设有专门的伦理审查流程：
- 双重用途相关问题
- 数据隐私问题
- 偏见与公平性方面的影响

## AAAI 审稿人指南

### 评估标准

AAAI 审稿人采用与 NeurIPS/ICML 类似的维度进行评估，但也存在一些差异：

| 标准 | 权重 | 说明 |
|-----------|--------|-------|
| **技术质量** | 高 | 方法是否可靠、结果是否正确 |
| **重要性** | 高 | 问题及论文贡献的重要程度 |
| **新颖性** | 中高 | 新思想、新方法或新见解 |
| **清晰度** | 中 | 写作清晰、内容组织良好 |
| **可复现性** | 中 | 是否提供了足以复现结果的细节 |

### AAAI 特有的考量

- **更广泛的 AI 范畴**：AAAI 涵盖整个人工智能领域，而不仅限于 ML。规划、推理、知识表示、NLP、视觉、机器人和多智能体系统等方向的论文均在征稿范围内。审稿人未必是深度 ML 专家。
- **严格的格式要求**：AAAI 要求审稿人标记违反格式规范的情况。不合规的论文可能在送审前就被直接拒稿。
- **应用型论文**：相较于 NeurIPS/ICML，AAAI 对以应用为重点的工作更为接纳。将有力的应用贡献作为论文的核心定位是可行的。
- **高级程序委员会**：AAAI 设有 SPC（高级程序委员会成员），负责协调审稿人意见并提出接收或拒绝建议。

### 评分（AAAI 量表）

- **强烈接收**：明显高于接收门槛，贡献出色
- **接收**：高于接收门槛，贡献良好，仅有少量问题
- **弱接收**：处于边缘，优点超过疑虑
- **弱拒绝**：处于边缘，疑虑超过优点
- **拒绝**：低于接收门槛，存在重大问题
- **强烈拒绝**：远低于接收门槛

## COLM 审稿人指南

### 评估标准

除通用标准外，COLM 评审还重点考察论文与语言建模的相关性：

| 标准 | 权重 | 说明 |
|-----------|--------|-------|
| **相关性** | 高 | 必须与语言建模学术共同体相关 |
| **技术质量** | 高 | 方法合理，主张有充分依据 |
| **新颖性** | 中高 | 对语言模型提出新见解 |
| **清晰度** | 中 | 表述清晰，研究可复现 |
| **重要性** | 中高 | 对 LM 研究与实践的影响 |

### COLM 特有的考量

- **聚焦语言模型**：审稿人会评估论文贡献是否推进了对语言模型的理解。通用 ML 贡献需要明确说明其与 LM 的联系。
- **新兴会议的评审规范**：COLM 的历史短于 NeurIPS/ICML，因此不同审稿人的评判尺度可能存在更大差异。写作时应更周全地预判质疑——审稿人的专业背景范围可能更广。
- **源自 ICLR 的流程**：审稿流程参照 ICLR 设计，包括公开评审、作者回复期以及审稿人之间的讨论。
- **对“语言建模”的宽泛界定**：包括 LM 的训练、评估、对齐、安全、效率、应用、理论、多模态（以语言为核心时）以及社会影响。

### 评分

COLM 采用类似 ICLR 的评分体系：
- **8–10 分**：强烈接收（顶尖论文）
- **6–7 分**：弱接收（贡献扎实）
- **5 分**：边缘
- **3–4 分**：弱拒绝（低于接收门槛）
- **1–2 分**：强烈拒绝

<a id="what-makes-reviews-strong"></a>

## 高质量评审的要素

### 遵循 Daniel Dennett 的原则

优秀的审稿人遵循以下原则：

1. **公平地复述论文观点**——表明你确实理解了论文
2. **列出认同之处**——肯定论文做得好的部分
3. **列出你从中学到的内容**——认可论文的贡献
4. **在此之后再提出批评**——先证明自己准确理解了论文

### 评审结构的最佳实践

**高质量评审的结构：**
```
Summary (1 paragraph):
- What the paper does
- Main contribution claimed

Strengths (3-5 bullets):
- Specific positive aspects
- Why these matter

Weaknesses (3-5 bullets):
- Specific concerns
- Why these matter
- Suggestions for addressing

Questions (2-4 items):
- Clarifications needed
- Things that would change assessment

Minor Issues (optional):
- Typos, unclear sentences
- Formatting issues

Overall Assessment:
- Clear recommendation with reasoning
```

<a id="common-reviewer-concerns"></a>

## 审稿人的常见关切

### 技术方面的关切

| 审稿意见 | 如何提前应对 |
|---------|-----------------|
| “基线太弱” | 使用当前最佳水平的基线，并引用近期工作 |
| “缺少消融实验” | 加入系统性的消融研究 |
| “没有误差线” | 报告标准差或误差，并进行多次运行 |
| “超参数未调优” | 记录调优过程与搜索范围 |
| “主张缺乏依据” | 确保每项主张都有证据支持 |

### 新颖性方面的关切

| 审稿意见 | 如何提前应对 |
|---------|-----------------|
| “贡献只是增量式改进” | 清晰说明相较于先前工作的新意 |
| “与 [paper X] 类似” | 在相关工作中明确与 X 进行比较 |
| “只是直接扩展” | 突出其中并非显而易见的方面 |

### 清晰度方面的关切

| 审稿意见 | 如何提前应对 |
|---------|-----------------|
| “难以理解” | 使用清晰的结构和引导性表述 |
| “符号不一致” | 检查所有符号，并制作符号表 |
| “缺少细节” | 加入可复现性附录 |
| “图表不清晰” | 使用信息完备的图注和合适的尺寸 |

### 重要性方面的关切

| 审稿意见 | 如何提前应对 |
|---------|-----------------|
| “影响有限” | 讨论更广泛的意义 |
| “评估范围狭窄” | 在多个基准上进行评估 |
| “仅适用于受限场景” | 坦诚说明适用范围，并解释其为何仍有价值 |

<a id="how-to-address-reviewer-feedback"></a>

## 如何回应审稿意见

### 答辩的最佳实践

**应当：**
- 感谢审稿人投入的时间
- 逐项具体回应每个关切
- 提供证据（如条件允许，可补充新实验）
- 保持简洁——审稿人的时间有限
- 承认合理的批评

**不应当：**
- 采取防御或轻蔑的态度
- 做出无法兑现的承诺
- 回避难以回应的批评
- 撰写过于冗长的答辩
- 与审稿人争论主观判断

### 答辩模板

```markdown
We thank the reviewers for their thoughtful feedback.

## Reviewer 1

**R1-Q1: [Quoted concern]**
[Direct response with evidence]

**R1-Q2: [Quoted concern]**
[Direct response with evidence]

## Reviewer 2

...

## Summary of Changes
If accepted, we will:
1. [Specific change]
2. [Specific change]
3. [Specific change]
```

### 何时应接受批评

有些审稿意见应当直接接受：
- 指出的技术错误确实存在
- 遗漏了重要的相关工作
- 解释不够清晰
- 缺少实验细节

应以得体的方式承认这些问题：“审稿人正确地指出……我们将修改为……”

### 何时应据理说明

在以下情况下，可以礼貌地表达不同意见：
- 审稿人误解了论文
- 要求补充的实验超出了论文范围
- 批评所依据的事实有误

应以建设性的方式表达分歧：“感谢审稿人提出这一看法。不过，[解释]……”

## 投稿前的模拟评审

投稿前，请自问：

**质量：**
- [ ] 如果我读到这些结果，我会相信它们吗？
- [ ] 所有主张是否都有证据支持？
- [ ] 基线是否公平且足够新？

**清晰度：**
- [ ] 他人能否仅根据论文复现这项工作？
- [ ] 对该子领域的非专家而言，文字是否清晰易懂？
- [ ] 所有术语和符号是否均已定义？

**重要性：**
- [ ] 学术共同体为什么应该关注这项工作？
- [ ] 人们可以利用这项工作做什么？
- [ ] 这一问题是否重要？

**原创性：**
- [ ] 这项工作具体有哪些新意？
- [ ] 它与最相近的相关工作有何不同？
- [ ] 其贡献是否并非微不足道？
